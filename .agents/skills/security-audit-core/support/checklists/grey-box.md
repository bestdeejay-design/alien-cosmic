# Чек-лист: Grey Box

> Режим: Black Box + частичное знание. Требуются тестовые аккаунты, документация, staging.
> Каждый пункт: `проверено / не проверено (причина) / не применимо`.

## Всё из Black Box

- [ ] См. [black-box.md](black-box.md) — выполняется полностью, но уже с тестовыми доступами.

## Доступы, роли, документация

- [ ] Тестовые аккаунты всех ролей получены и сверены (клиент/игрок, модератор, админ, мерчант/оператор).
- [ ] API-документация (OpenAPI/Postman) сверена с фактическими эндпоинтами.
- [ ] Схема потоков: регистрация, оплата, выдача валюты/услуги, торговля, вывод.
- [ ] Staging соответствует проду по конфигурации (кроме данных); расхождения зафиксированы.

## Авторизация между ролями

- [ ] AuthZ на каждый объект: чужой профиль/инвентарь/счёт/выписка/документы (IDOR).
- [ ] Вертикальная эскалация: клиент → модератор → админ; горизонтальная: клиент → клиент.
- [ ] Tenant isolation: workspace/клиент не видит чужие данные.
- [ ] Админка/саппорт: права, аудит действий, MFA, временный доступ.

## Логика, состояние, гонки

- [ ] Race conditions: параллельные покупки/переводы/выводы/передачи.
- [ ] Идемпотентность: повтор POST/PATCH/вебхука не создаёт дубль.
- [ ] Транзакционность: частичная запись, откат, обрыв сети в середине операции.
- [ ] Отрицательные/нулевые/переполненные суммы и количества; подмена цены/количества с клиента.
- [ ] Сессии/токены: отзыв, ротация, время жизни, хранение на клиенте.

## Деньги и валюта (по домену)

- [ ] Игра: дюп, фарм, торговля, донат, RNG — см. [gaming.md](gaming.md).
- [ ] Финтех: ledger, double spend, вебхуки, KYC/AML, PII — см. [fintech.md](fintech.md).

## Файлы, загрузки, интеграции

- [ ] Загрузки: типы, размеры, хранение, доступ по прямым ссылкам, вредоносное содержимое (в scope).
- [ ] Вебхуки: подпись, replay, идемпотентность, порядок, статусы.
- [ ] Интеграции: ключи, scopes, лимиты, отзыв; секреты не уходят в клиент/логи.
