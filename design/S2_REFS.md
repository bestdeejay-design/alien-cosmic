# S2 REFS — референсы из «Рубеж 64» (minigames/rubezh64) для механик Сезона 2

> Дайджест приёмщика (2026-10-20). Источник — репо `bestdeejay-design/minigames`,
> игра `rubezh64/` (эталон визуала Alien Cosmic). Второй RTS в hub — `rts/`
> («Звёздный рубеж») — разведчиков/ретрансляторов не содержит.
> Всё ниже проверено по коду rubezh64; числа — стартовые ориентиры для
> баланс-агента S2 (SCENARIO.md §0: числа на усмотрение баланс-агента).

## 1. Ретрансляторы (референс для §1/М6/М11/М12 сценария)

`rubezh64/js/relays.js` (56 строк) — цельный модуль:

- **Сущность**: нейтральный объект `{ kind:'relay', owner:null, control:0 }`,
  3 штуки на карте 64×64 (сайты [20,11], [32,36], [44,53]); спавн с поиском
  свободного тайла спиралью до r=6 (fallback-ошибка, не тихий сбой).
- **Захват**: контроль ±1 за `relayCaptureSeconds: 9` при присутствии юнитов
  одной стороны в `relayRadius: 55` px; при обоих — заморозка. Потеря
  контроля → owner сбрасывается через ноль (не мгновенно).
- **Эффект владельца**: пассивный доход `relayIncome: 2.5` мин/с + обзор
  `relayVision: 8` тайлов (fog).
- **Обратная связь**: анонсы в лог (владелец/потеря, разные тоны) + звук
  (`relay`/`error`); счётчик `relayCount(team)` для UI/целей.

### Отличие от сценария S2 (важно!)

Сценарий хочет **сеть связи**: ретранслятор в состояниях off/on/destroyed,
включает ТОЛЬКО герой, связь даёт КЦ автономию (`networkLinked`), разрыв =
слепая база. rubezh64 — это **очки захвата с доходом**: proximity-контроль
любым юнитом, эффект — экономика, не связь. Для S2 переиспользуем:
скелет сущности (owner/control/таймер), таймер-флип, анонсы, vision-радиус,
UI-счётчик. Переосмысляем: включение героем (каст), тройка состояний,
эффект → `networkLinked` у КЦ. Доход rubezh64 можно оставить как вторичную
награду удержания (решение диздока S2).

## 2. Разведчик (референс для «Следопыта» М1 и разведки КЦ М10)

`rubezh64/js/config.js` UNIT_TYPES.scout: **Разведчик (СКТ)** — hp 65,
speed 132 (быстрейший), vision 11 (самый глазастый), range 105, dmg 5,
cost 65, train 7 с, supply 1; строится казармой (2-й продукт).

- **AI-паттерн** `ai.js scoutRelay` (79–103): ИИ держит ровно одного
  разведчика (`hasScout` учитывает и очередь казармы), покупает после t=55 с;
  разведчик живёт задачей `relayMission` — идёт захватывать свободный
  ретранслятор, освобождается при потере цели. Прямой прообраз «КЦ шлёт
  разведку» (М10 сценария).
- **Поводок**: автозащита в rubezh64 привязана к дому — «один разведчик не
  должен выманить весь гарнизон» (units.js:186) — тот же принцип, что
  принят в H.3/М1 (безопасный обход тумана).

### Отличие от S1/S2

В S1 «Следопыт» (H-код) — **безоружный** (dmg 0, 5 затворов), 60/12 с,
hp 50, speed 185, vision 11. Референс rubezh64 вооружён (dmg 5) — S2-М1
использует S1-юнита как есть + скрытность даёт механика «Троп» (зоны),
а не стелс-поле юнита. Дрон-компаньон из описания М3 сценария — свежий
дизайн, референса нет.

## 3. Чего в референсах нет (свежий дизайн S2)

Герои (аура/не-смерть), Тропы (стелс-зоны), персистентность состава между
миссиями, мораль/паника, диверсия/саботаж, ложные сигналы, дилемма
эвакуации, две концовки. Ретрансляторный скелет и AI-паттерн разведки —
единственные готовые куски.

## 4. Порядок для S2

При S2-киккоффе: диздок главы 2 (рetrosляторы/сеть) опирается на §1 этого
файла; диздок разведки М10 — на §2. Перф-прикидка для 128×128 (М12/14/15):
fog-тиковая схема rubezh64 (`fogRefreshSeconds: .25`) — ориентир бюджета.
