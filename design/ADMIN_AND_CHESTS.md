# Капсулы снабжения и панель админа (Э6)

Документ описывает призовую систему полигона `r/`: терминологию, модель данных,
правила выдачи, антиабуз и план «хайпа» для школьной аудитории. Код:
`r/js/chests.js` (движок), `r/js/chests-ui.js` (карточки и вскрытие),
`r/js/admin.js` (панель), серверные эндпоинты — `server/save-server.mjs`.

---

## 1. Терминология

| Термин | Что это | Где живёт |
|---|---|---|
| **Капсула** | Контейнер с наградой, который «падает» на базу игрока | карточка в оверлее `#chest-overlay` |
| **Рарность** | common → rare → epic → legend: цвет карточки, свечение, приоритет в списке | `RARITY` в `chests.js` |
| **Условие** | Кому капсула доступна (окно входа, ДР, N рейдов, топ, уровень КЦ) | `CONDITIONS` |
| **Период** | `day` — раз в сутки, `once` — раз в жизни | поле `period` |
| **Награда** | Эрг, юнит, грейд здания, ранг юнитов, бустер добычи, облик | `REWARD_KINDS` |
| **Вес** | Относительная вероятность награды внутри капсулы | поле `weight` |
| **Подарок администрации** | Ручная выдача конкретному нику через `/api/grant`, приходит как legend-капсула `once` | серверный ключ `ac_grant` |

Слово «сундук» не используем: во вселенной игры это **капсула снабжения** —
контейнер, сброшенный с орбиты.

## 2. Модель данных

Конфиг целиком (одна запись в localStorage `ac_chest_cfg_v1` и на сервере
`ac_chest_cfg`):

```json
{
  "schemaVersion": 1,
  "enabled": true,
  "showOnEntry": true,
  "chests": [
    {
      "id": "evening-drop",
      "name": "Вечерний сброс",
      "desc": "Капсула с орбиты для тех, кто зашёл с 20:00 до 20:30.",
      "icon": "capsule",
      "rarity": "rare",
      "condition": { "type": "window", "params": { "from": "20:00", "to": "20:30" } },
      "period": "day",
      "rewards": [
        { "kind": "erg",   "params": { "amount": 1200 }, "weight": 60 },
        { "kind": "unit",  "params": { "unit": "marine", "count": 3 }, "weight": 25 },
        { "kind": "boost", "params": { "mul": 1.5, "minutes": 20 }, "weight": 15 }
      ]
    }
  ]
}
```

Состояние «уже забрал» — отдельный ключ `ac_chest_state_v1`:

```json
{ "claimed": { "daily": { "day": "2026-10-25", "ts": 1792957220709 } }, "seen": {} }
```

Идентификаторы: `id` капсулы задаёт админ (или генерируется `chest-<ts36>`).
По `id` считается «забрано», поэтому **переименование капсулы не сбрасывает
отметку**, а новый `id` — это новая капсула.

### Таблица условий

| `type` | Параметры | Смысл | Пример |
|---|---|---|---|
| `always` | — | доступна всем и всегда | подарок админа, акция «просто так» |
| `daily` | — | раз в сутки, всегда в списке | ежедневная капсула |
| `window` | `from`, `to` (`HH:MM`) | кто зашёл в окно; корректно работает через полночь | «вечерний сброс 20:00–20:30» |
| `birthday` | — | дата рождения (ДД.ММ) в профиле браузера сегодня | капсула именинника |
| `raids` | `n` | сколько вылетов сделано (счётчик сессии) | «20 рейдов» |
| `loot` | `n` | сколько эрга добыто на вылазках | «50 000 эрга» |
| `cc` | `n` | уровень КЦ | «после КЦ-X» |
| `top` | `n`, `metric` (`raids`\|`loot`) | место в рейтинге сервера | «топ-100 по рейдам» |

Если условие не выполнено, карточка показывается **закрытой с причиной**
(«нужно вылетов: 20», «окно 20:00–20:30», «нужен топ-100»): игрок видит
цель, а не пустоту.

### Таблица наград

| `kind` | Параметры | Что делает | Ограничения |
|---|---|---|---|
| `erg` | `amount` | зачисляет эрг на базу | — |
| `unit` | `unit`, `count` | ставит юнитов у КЦ (до 20 шт.) | тип из `UNITS` |
| `grade` | `building`, `levels` (1–5) | поднимает грейд здания | **не выше уровня КЦ (R1)**, максимум 20 |
| `tech` | `key`, `levels` (1–5) | поднимает ранг юнитов | суммарно до 20 |
| `boost` | `mul` (1–3), `minutes` (1–240) | множитель добычи на время | действует на сдачу груза |
| `cosmetic` | `id` | выдаёт облик (заготовка под Э7) | — |

Вес награды — относительный: `60/25/15` значит 60 %, 25 %, 15 %. Сим
`sim_r_raid20.mjs` (блок E12) проверяет сходимость весов на 10 000 бросков
(допуск ±3 п.п.), поэтому «подкрутить веса в админке» нельзя незаметно
сломать: числа остаются числами.

## 3. Как это выглядит в игре

Канон владельца: **никаких новых кнопок в топбаре**, механика живёт в строениях
и на экране.

1. **Вход на базу.** Если есть доступные капсулы, через ~0.9 с поднимается
   оверлей «КАПСУЛЫ СНАБЖЕНИЯ» (не чаще раза за сессию). Игра встаёт на паузу.
2. **Карточка.** Рарность, иконка (SVG рисуется кодом — внешних ассетов нет),
   название, описание и состояние: «готова к вскрытию» / «забрана» /
   причина закрытия.
3. **Вскрытие.** Один тап: вспышка в цвет рарности, крупный текст награды,
   кнопка «Забрать и продолжить». Награда сразу применяется к состоянию игры
   и дублируется тостом.
4. **Повторно** список открывается командой КЦ **«Капсулы»** (`KeyC`).
5. **Панель админа** — команда КЦ **«Админ»** (`KeyO`), вход по PIN.
6. **Дата рождения** вводится из карточки капсулы (кнопка «указать ДР», формат
   `ДД.ММ`) и хранится локально.

Мобильный приоритет: сетка 2 колонки ≤560 px, карточки ≥158 px высотой,
тап-цели ≥40 px, оверлей скроллится внутри, футер с кнопкой «На базу».

## 4. Панель админа

Открывается командой КЦ «Админ». PIN по умолчанию `1234` (стенд!), меняется в
разделе «Диагностика», хранится в localStorage браузера. Вход действует на
вкладку сессии (`sessionStorage`), после перезагрузки спрашивается снова.

| Вкладка | Что делает |
|---|---|
| **Экономика** | масштаб цен 0.02–2× с пресетами («Канон 1.0», «Тест 0.2», «Быстрый прогон 0.05»). Применяется после перезагрузки; `?econ=` в адресе имеет приоритет |
| **Капсулы** | список капсул, создание/правка/удаление, редкость, период, иконка, условие с параметрами (JSON), награды с весами, переключатели «показывать при входе» и «капсулы включены», «Заводской набор», «Опубликовать на сервер» / «Забрать с сервера» |
| **Игроки** | топ по рейдам/добыче с сервера (`/api/top`), таблица (место, ник, вылеты, добыто, КЦ, Дом) и ручная выдача: эрг + грейд Дома через `/api/grant` с токеном `ADMIN_PIN` |
| **Диагностика** | режим, эрг, КЦ, Дом (грейд, отсек), вылеты, добыча, число капсул, список «забрано», профиль сейва, канал API, масштаб цен; кнопки «Сбросить забранное» и «Сбросить сейв базы», смена PIN |

Все ошибки ввода (битый JSON параметров или наград) показываются строкой
статуса и **не сохраняются** — проверено симом U4.

## 5. Антиабуз

Призы — это контент, а не товар. Никаких покупок, валюты за деньги и
«круток» в игре нет и не планируется.

1. **Нет монетизации.** Капсулы нельзя купить, продать или обменять. Все
   награды — внутриигровой эрг/юниты/грейды.
2. **Прозрачность.** В админке видны и веса, и условия. Игрок видит причину
   закрытия капсулы. Мы не скрываем шансы.
3. **Ограничение частоты.** `period: day` — не чаще одного раза в сутки;
   `period: once` — раз в жизни. Отметки хранятся по `id`, сервер их не
   «прощает».
4. **Приз не ломает канон.** Грейд из капсулы не поднимает здание выше КЦ
   (R1), юниты приходят обычные, ранги считаются по тем же таблицам.
5. **Приз не заменяет игру.** Ориентир: суммарная дневная выдача капсул
   ≤ 20–25 % дохода одного рейда текущего тира. Иначе игрок начинает
   «заходить за капсулой» вместо того, чтобы летать (см. §7).
6. **Подарки — адресные.** `/api/grant` пишет в ключ `ac_grant` **того нику**,
   который указан, и требует `ADMIN_PIN` (Bearer-токен), если переменная
   окружения задана. Без `ADMIN_PIN` эндпоинт открыт — это режим стенда,
   на публичном адресе его нужно ставить обязательно.
7. **Профиль = ник + PIN.** Подарок нельзя «перехватить» другим ником; PIN
   проверяет сервер при чтении/записи ключей.
8. **Ограничение сверху.** `unit` ≤ 20 юнитов за награду, `grade` ≤ 5 уровней,
   `boost` ≤ ×3 и ≤ 4 часов, эрг — на усмотрение админа, но с оглядкой на п.5.
9. **Время.** Окно входа и ДР считаются по локальным часам браузера. Для
   школьного стенда это приемлемо; если когда-нибудь появится соревновательный
   смысл, окно надо считать по серверному времени (`ts` уже пишется в сейв).
10. **Сброс состояния** доступен только в панели админа (PIN) — игрок не может
    «переоткрыть» капсулу, почистив localStorage, потому что отметки уходят на
    сервер вместе с сейвом профиля.

## 6. Идеи «хайпа» для школьной аудитории

Ограничение: без давления, без «успей купить», без сравнения кошельков. Хайп
строим на **событии и общем вечере**, а не на страхе потери.

1. **Вечерний сброс 20:00–20:30** (уже в наборе). Класс заходит в одно время —
   в чате/на перемене есть общая тема: «кто что вытащил».
2. **Капсула именинника.** Личный повод зайти и повод классу поздравить.
   Не «подарок за активность», а человеческое событие.
3. **Капсула рейдера (20 вылетов).** Цель на неделю: 20 вылетов = заметный
   шаг (грейд Дома), а не мелочь.
4. **Капсула лидера (топ-100).** Рейтинг по вылетам и добыче — здесь важен
   «порог входа»: попасть в топ-100 реально за вечер, а не за месяц.
5. **Сезонные капсулы.** «Первый снег», «последний звонок», «новый год» —
   дата в условии `window`/`always` на 1–2 дня. Плюс: их можно выдавать
   вручную через `/api/grant` всему классу по списку ников.
6. **Капсула-задание.** Условие `loot` (добыть N эрга) превращает приз в
   задачу, а не в лотерею: игрок понимает, что делать.
7. **Классный турнир на перемене.** 10 минут, режим быстрого прогона
   (`?econ=0.1`), победителю — legend-капсула вручную. Хорошо работает как
   демо на уроке информатики.
8. **«Капсула друга».** Приз, который можно активировать только вдвоём
   (например, бустер добычи действует всей базе) — социальный, не денежный.

Чего **не** делаем: платных капсул, «круток за просмотр рекламы», таймеров
«осталось 3 минуты», уведомлений «твой друг получил легендарку», рейтинга по
деньгам.

## 7. Ресёрч: что говорят данные

Коротко и по делу, с выводами для нашего стенда.

**Ежедневные награды и серии.** Отраслевые обзоры сходятся: ежедневные награды
поднимают 30-дневное удержание в среднем на ~19 %, а ключевой показатель —
не «30 дней», а привычка к 7-му дню: серия в 7 дней лучше всего предсказывает
долгосрочное возвращение. При этом «прощение пропуска» (freeze) увеличивает
среднюю длину серии в разы — запрет на пропуск скорее отпугивает, чем
мотивирует ([Playio](https://blog.playio.co/dau-by-game-genre-mobile-games-2026),
[Trophy: Duolingo case](https://trophy.so/blog/duolingo-gamification-case-study),
[Blox Beacon](https://bloxbeacon.com/daily-login-rewards-guide/)).
→ *У нас:* нет штрафа за пропуск; `period: day` просто доступен снова на
следующий день, никаких «серия сгорела».

**Правило «награждай фантазию, а не вход».** Если награда выдаётся за факт
входа, игрок учится кликать «забрать» и уходить. Награда должна быть связана с
действием в игре ([r/GameDevelopment](https://www.reddit.com/r/GameDevelopment/comments/1tczba2/a_simple_design_rule_for_daily_rewards_reward_the/)).
→ *У нас:* половина капсул привязана к действиям (`raids`, `loot`, `cc`), а
ежедневная — сознательно маленькая (400–1200 эрга), чтобы не заменять рейд.

**Гарантия («pity») и её этика.** Гарантированный приз после N попыток снижает
фрустрацию, но в платных системах он же становится «двигателем sunk cost»:
исследования и комментарии к политике регуляторов отмечают, что pity-механики
усиливают вовлечение в трату
([Springer](https://link.springer.com/article/10.1007/s11469-019-00164-4),
[MDPI](https://www.mdpi.com/2078-2489/16/10/890)). Регуляторы требуют
раскрывать шансы платных случайных предметов (Apple/Google), FTC оштрафовала
HoYoverse за непрозрачные вероятности
([zaplat](https://zaplatgaming.com/articles/gaming-gacha-loot-box-odds-pity-currency-real-cost-fairness-2026-en),
[BleepingComputer](https://www.bleepingcomputer.com/news/gaming/ftc-cracks-down-on-genshin-impact-gacha-loot-box-practices/)).
→ *У нас:* капсулы **бесплатные**, шансы видны в админке, и вместо «круток»
работает гарантия по времени/действию: ежедневная капсула даёт что-то каждый
день, поэтому «пустых» дней нет вовсе.

**Дети и подростки.** Обзоры подчёркивают: у подростков импульс-контроль ещё
формируется, поэтому давление (таймеры, «друг получил», покупки в один тап)
действует сильнее. Требования к дизайну — прозрачность, лимиты, отсутствие
покупок для младших
([Digital Safety](https://www.digitalsafetychildren.com/loot-boxes-explained-parents/),
[Salivity](https://salivity.github.io/game-development/article/ethical-loot-box-design-in-game-development)).
→ *У нас:* нет покупок вообще, нет обратного отсчёта, максимум — «окно
20:00–20:30», которое повторяется каждый день.

**Ориентиры удержания (чтобы не требовать невозможного).** Медианные D1 ≈ 25–
30 %, D7 ≈ 10–15 %, D30 ≈ 3–6 % для мобильных игр
([AppAgent](https://appagent.com/blog/mobile-game-retention-benchmarks/),
[Mistplay](https://business.mistplay.com/resources/player-retention)).
→ *У нас:* школьный стенд живёт «вечерами» и на переменах; ориентир — не
D30, а «сколько человек зашли в 20:00 и сколько из них сделали рейд».

## 8. Как проверить руками

```bash
node scripts/check_r.mjs        # изоляция r/ + UI капсул (вложенно)
node scripts/sim_r_raid20.mjs   # E12: условия, веса, выдача, «раз в день»
node scripts/sim_chests_ui.mjs  # U1–U5: оверлей, вход, админка, конструктор
node server/save-server.mjs     # /api/top, /api/grant
POLYGON=1 PORT=8806 node server/static.mjs   # стенд: / → /r/
```

В браузере:

1. Зайти на стенд, дождаться карточек → забрать ежедневную.
2. КЦ → «Капсулы» → проверить, что забранная помечена.
3. КЦ → «Админ» → `1234` → «Капсулы» → создать капсулу с условием `raids: 1`
   → перезайти → она должна быть открыта.
4. «Игроки» → «Обновить топ» (нужен сейв и профиль) → «Выдать» подарок.
5. «Диагностика» → «Сбросить забранное» → карточки снова доступны.

## 9. Что дальше (кандидаты)

* Серверный конфиг капсул как **единственный** источник (сейчас локальный +
  публикация вручную, чтобы стенд жил без сети).
* История выдач на сервере (`ac_grant_log`) — чтобы видеть, что и кому ушло.
* «Капсула класса»: один общий счётчик на всех, кому сколько досталось —
  мотивация без личного соревнования.
* Облики (`cosmetic`) — связать с Э5 (фазы вида) и выдавать как награду.
* Pity-подобная гарантия для редких наград: «если 5 дней подряд только эрг —
  на шестой падает юнит». Бесплатно и без давления.
