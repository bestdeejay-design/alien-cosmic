## 3. Предлагаемая архитектура UI (r/ui3/)

### 3.1. Компонентная структура

Новый слой — `r/ui3/` (рядом с `r/js/`, отдельная папка = чистая граница миграции):

```
r/ui3/
  kit/            — базовые кирпичи (без игровой логики)
    dom.js        — h()/el() вместо HTML-строк; typed-обновление полей
    panel.js      — ЕДИНАЯ панель-модалка: шапка/тело/футер, bottom-sheet на телефоне,
                    center-dialog на десктопе; регистрация в modals.js (не дублируем)
    toast.js      — очередь с приоритетами (alarm > warn > info), action-кнопка в тосте
    topbar.js     — топбар-виджеты: данные + отсчёты, точки останова
    field.js      — значение с лейблом/иконкой (эрг, население, XP)
  screens/        — экраны-компоненты (каждый = функция mount/unmount)
    commander-v2.js — карточка командира: ДВА варианта на стенд (решение владельца Б2):
                      табы (Обзор / Оборона / Тревога / Навыки / Журнал) и секции-скролл;
                      выбор — за владельцем после просмотра стенда
    expeditions.js  — таб «Экспедиции»: ПЕРВЫМ экраном кнопка запуска (Б3), журнал
                      вылеток из alarm-v2-store свёрнут ниже
    alarm-banner.js — индикатор фазы атаки (Б1), см. §3.6
    (панель профиля НЕ переносится в ui3 — остаётся в КЦ, решение владельца Б4)
  state.js        — тонкий стор-адаптер: подписка на window.game / game.raidSession
                    (никакой своей логики — только re-render по dirty-флагам)
```

### 3.2. Единая система панелей/тостов

- **panel.js**: один механизм (overlay + box + aria-modal + `registerModal` из `r/js/modals.js`).
  Профили: `phone` → bottom-sheet во всю ширину, высота ≤86vh, tab-bar внизу, свайп вниз = закрыть;
  `tablet/desktop` → центр-диалог шириной `min(92vw, Npx)` (как сейчас), двухколоночная сетка опциональна.
- **toast.js**: приоритеты (alarm не перебивается info), максимум 3 как сейчас, ttl по классу
  (alarm — до прочтения, info — 2.25 с как сейчас), опциональная кнопка действия («Открыть профиль»).
- Все inline-стили существующих панелей переносятся в `r/ui3/ui3.css` с токенами из
  design/COMPONENT_CATALOG.md (DS-1: палитра-токены, никакого сырого hex).

### 3.3. Топбар с данными (домашняя база)

Состав по умолчанию в home-режиме: **эрг** · **население (supply)** · **отсчёт тревоги —
ВСЕГДА виден** (решение владельца Б1; поднимаем `#res-alarm` из `display:none`, активная
атака раскрывается в alarm-banner §3.6) · КЦ-уровень ·
индикатор синка сейва (точка: зелёная/серая/красная — данные уже есть в `window.__saveApi.status`).
На телефоне — компакт: только эрг/население/тревога, остальное по тапу (dropdown-шторка).
Канон «в топбаре нет входа/профиля» — соблюдается: профиль только из КЦ.

### 3.4. Карточка командира v2

- Табы: **Обзор** (звание, XP, бонусы, статистика) · **Оборона** (статус рейда, автозащита,
  посты, отступ/сброс, salvage) · **Тревога** (v2: режимы, осада, запуск/сдача, отчёт,
  восстановление) · **Навыки** · **Журнал**.
- **Решение владельца Б2 — поиграть ОБА варианта.** До выбора: стенд `stands/`
  (окно 600×800 — канон стендов) с двумя вариантами карточки: A = табы, B = секции-скролл
  (текущая компоновка, причесанная на kit). Реализация начинается после выбора владельцем.
- **Канон COMMANDER2_SPEC: rollback в карточке v2 НЕТ.** Кнопка «откат» (сейчас
  `#alarm-rollback` → `rollbackAlarmEvent`, `r/js/alarm-v2-director.js:132`) не переносится:
  потери необратимы, откат — не часть интерфейса. Удаление `rollbackAlarmEvent` и
  связанного `preBattleDto` из `alarm-v2-director.js` — предэтап U2a (или отдельная
  поставка до U2): только удаление мёртвого пути, без переделки UI.
- Кнопка «Запустить тревогу» — крупная (48px+) в футере таба «Тревога» и дублем в «Обзоре» при
  IDLE-фазе; в активной фазе карточка открывается сразу на статусе.
- Refresh: точечные апдейты через state.js (1 Гц как сейчас), но с dirty-проверкой по секциям.

### 3.5. Таб «Экспедиции» (решение владельца Б3)

Первым экраном — крупная кнопка запуска вылетки; журнал вылеток (сейчас как UI его нет —
данные лежат в снапшоте `alarm-v2-store`, cap 60 записей, SCALING_SAVES §1) — свёрнутый
блок ниже (список: дата, результат, bounty, XP; фильтр тренировка/боевая). Читает из той же
структуры, пишет ничего — однонаправленно.

### 3.6. Тревога (компонент alarm-banner, решение владельца Б1)

**Отсчёт тревоги в топбаре — ВСЕГДА виден** (в home-режиме; поднимаем `#res-alarm`).
При активной атаке сверху экрана — полноширинный индикатор фазы `alarm-banner.js`.
Машина состояний (данные: `homeRaidStatus`, `alarmUiState` из alarm-v2-director):

| Состояние | Вид | Данные |
|---|---|---|
| покой (IDLE, alarm включена) | тонкая строка под топбаром: «Тревога через М:СС» | `rs.countdown` |
| отсчёт до атаки (≤60 с) | та же строка + пульсация, крупный отсчёт | `rs.countdown` |
| фаза атаки (WARNING / WAVE / BREAK) | полоса прогресса фазы + **волны точками**: ●●○○○ (пройдено/осталось), подпись фазы и «волна N/5» | `ast.phase`, `ast.wave`, `ast.totalWaves` |
| итог (victory/defeat) | краткий итог 4–6 с (bounty/payout) → сворачивается в строку покоя; полный отчёт — в карточке командира, таб «Тревога» | `ast.report` |

Правила: высота ≤44px (не перекрывает зону пальца), тап → карточка командира на табе
«Тревога»; звук не дублируется (audio.js уже есть); on phone — полоса на всю ширину,
точки волн ≥12px. Тост-канал `alarm` — пульсирующий, с действием «К обороне».

### 3.7. Адаптивная сетка (контракт)

**Решение владельца Б5: тулбар строений остаётся ВНИЗУ экрана** (мобильный тач-приоритет —
зона большого пальца); боковые позиции нижней панели — десктопное наследие, на phone не применяются.

| Профиль | Источник | Поведение |
|---|---|---|
| phone (<768 или coarse pointer + узко) | ScreenProfile | **нижний тулбар строений** (Б5), bottom-sheet панели, топбар-компакт (эрг/население/тревога), зум-кнопки 48px (уже есть) |
| tablet (768–1180) | ScreenProfile | нижний тулбар или боковая панель (`body.panel-left/right`), панели-диалоги, топбар полный |
| desktop (>1180) | ScreenProfile | как tablet + двухколоночные карточки, hover-хинты |
