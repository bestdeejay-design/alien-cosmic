# MOBILE_VIEWPORT_AUDIT.md — мобильный viewport: зум-ловушка и отрезанный край

Процесс: аудит → ресерч → выводы → варианты → (код отдельным пакетом после выбора).

## §1. Репорт владельца (22.10.2026, игра с телефона)

> «правая часть экрана примерно на четверть или пятую часть от края делает невидимыми
> строения и юниты, и не закреплен вьюпорт, который при двойном тапе может увеличить
> экран до максимального масштаба, и при открытой панели потом никак не выйти из него.
> я думаю тут спасет на текущий момент сохранение текущего состояния и перезагрузка
> экрана, но я боюсь так мы наделаем делов»

Два симптома:
- **С1**: правые ~20–25% ширины экрана не показывают юниты/строения.
- **С2**: двойной тап зумит страницу; после этого из состояния нет выхода (панель открыта/на экране).

Гипотеза проверки: это **не два бага, а одна связка** — страница зумится браузерным
жестом там, где touch-action это разрешает; игра привязана к layout viewport и не
знает о visual viewport; канвас съедает жесты (`touch-action: none`) и не даёт
выбраться. С1 — прямое следствие С2.

## §2. Репродукция

Скрипт `scripts/mobile_zoom_repro.mjs` (Playwright, iPhone-эмуляция 390×844 dpr3
isMobile+hasTouch; зум — детерминированный CDP `Emulation.setPageScaleFactor`,
т.к. headless не исполняет сам жест двойного тапа — жест на живом устройстве
подтверждён репортом владельца). Лог: `tool-results/mobile/audit_full.log`.

Метрики до/после:

| Метрика | зум = 1 | зум = 1.4 |
|---|---|---|
| `window.innerWidth` (layout) | 390 | **390 — не изменился** |
| `visualViewport.width` | 390 | **278.6** |
| `visualViewport.scale` | 1 | 1.4 |
| канвас (CSS, rect) | 390×844 | **390×844 — не изменился** |
| `game.cssW` | 390 | **390 — игра не заметила** |
| скрытая правая полоса | 0 | **111.4 px = 28.6% ширины** |

- При 1.25x отрезается 20%, при 1.33x — 25% — совпадает с «четверть/пятая часть»
  из репорта: двойной тап Safari зумит на ~1.25–1.4x за шаг.
- Скриншоты-пара: `tool-results/mobile/Z1_scale1_rightedge.png` (полный HUD) и
  `Z2_scale14_rightedge.png` (топбар обрезан — кнопки «рестарт/×» за краем,
  **вся нижняя панель с миникартой ушла за нижний край**). Прыжки камеры и
  миникарта не помогают: отрезан сам канвас, а не мир в нём.
- `resize`-событие при зуме не приходит (layout viewport не меняется); даже там,
  где iOS исторически шлёт `resize` на пинч, `window.innerWidth` остаётся
  прежним — текущие слушатели (game.js:111–128) не лечат.

## §3. Корень (одна связка)

**А. Странице разрешено зумиться.** `index.html:5` — meta без ограничений:
`width=device-width, initial-scale=1`. Эффективный touch-action = пересечение по
цепочке предков (MDN); там, где вся цепочка `auto`, браузерный double-tap/pinch
разрешён. Аудит всех видимых элементов боевого экрана (25 шт.) нашёл зоны:

| Поверхность | Площадь, px² | double-tap | pinch |
|---|---|---|---|
| html / body / #game-root (фон, зазоры) | 329 160 | да | да |
| #bottom-panel (вся командная палуба) | 93 594 | да | да |
| #sel-info | 35 857 | да | да |
| .hint (хинт-тосты) | 27 069 | да | да |
| #topbar | 20 280 | да | да |
| #minimap-box | 20 164 | да | да |
| #panel-ctl | 6 114 | да | да |
| .mini-btn, .tb-btn (кнопки) | 1 900–3 500 | нет* | да |

\* кнопкам выставлен `touch-action: manipulation` (style.css:86 и др.) — double-tap
закрыт, но **pinch manipulation разрешает**. Т.е. пинч возможен с любой панели,
двойной тап — с любого «фонового» места, панелей и меню.

**Б. Игра живёт в layout viewport и не выпускает из зума.**
- `game.js resize()` (342–367) читает `window.innerWidth/innerHeight`; канвас —
  `#game-root { position: fixed; inset: 0 }` + `#game-canvas { inset: 0 }`.
  При зуме layout не меняется → игра не пересчитывается → правая/нижняя часть
  канваса за пределами visual viewport (С1).
- `#game-canvas { touch-action: none }` (style.css:47) — правильно для игры
  (свой зум щипком, свои жесты), но в зуме это же **блокирует родной пан и
  щипок-назад** по всей площади канваса. Панели мелкие и чаще всего за краем
  (скрин Z2) → «никак не выйти» (С2). Теоретический спасательный круг — щипок
  с топбара — существует, но его невозможно найти.

**Вывод В-корень:** лечить надо причину (не дать странице зумиться), а не симптом
(спасаться перезагрузкой). Геометрические `@media` и профиль ввода (пакет U) тут
ни при чём — это третья, независимая ось: **политика браузерных жестов страницы**.

## §4. Что не сработает или работает наполовину

- **`user-scalable=no` / `maximum-scale=1` в meta** — Android уважает, iOS Safari
  **игнорирует с iOS 10** (доступность): пинч и двойной тап останутся. Как
  единственная мера — insufficient; как дополнение — безвредно.
- **preventDefault на touchend/double-tap-хаки** — ломают клики, вносят задержки,
  конфликтуют с жестовым FSM пакета T. Отвергнуто.
- **Идея владельца «сейв + перезагрузка экрана»**: системы сохранений партии в
  игре нет (localStorage хранит только прогресс кампании/настройки). Сериализация
  живой партии (юниты, здания, туман, пути, ИИ, экономика) — большой продуктовый
  функционал, а `location.reload()` зум сбрасывает, но прогресс миссии теряет.
  Как костыль от зума — стрельба из пушки по воробьям; опасение владельца
  «наделаем делов» обосновано. Как самостоятельная фича (сейв/лоад в паузе) —
  имеет ценность, но это отдельный трек с отдельным аудитом.

## §5. Ресерч (источники)

1. **MDN — touch-action**: `manipulation` разрешает пан/пинч и запрещает
   double-tap; бонус — убирает задержку клика; эффективное значение =
   пересечение по цепочке до реализующего жест элемента (viewport).
   https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/touch-action
2. **StackOverflow 70745886** (prevent pinch iOS): `touch-action: pan-x pan-y`
   (=без `pinch-zoom`) закрывает и пинч, и double-tap, сохраняя нативный скролл.
   https://stackoverflow.com/questions/70745886/prevent-site-zoom-with-two-fingers-ios
3. **StackOverflow 37808180 + lukeplant.me.uk (2023)**: iOS 10+ игнорирует
   `user-scalable=no`/`maximum-scale=1` для жестов пользователя; пинч на iOS
   блокируется только `preventDefault` на `gesturestart` (iOS-специфичное
   событие) или touch-action.
   https://stackoverflow.com/questions/37808180/disable-viewport-zooming-ios-10-safari
   https://lukeplant.me.uk/blog/posts/you-can-stop-using-user-scalable-no-and-maximum-scale-1-in-viewport-meta-tags-now
4. **Mozilla — VisualViewport API**: `visualViewport.scale/width/height/
   offsetTop/offsetLeft`, событие `resize` — способ узнать про «чужой» зум
   (в т.ч. системный iOS-зум трёх пальцев, который веб заблокировать не может).
   https://developer.mozilla.org/en-US/docs/Web/API/VisualViewport

Доступность (WCAG 1.4.4 «Resize Text»): запрет PAGE-зума допустим, когда
функциональность зума предоставлена приложением — у игры есть собственный зум
щипком на канвасе и зум-кнопки (пакет U), мир масштабируется ZOOM_MIN–ZOOM_MAX.
Функциональность не теряется — переезжает под контроль игры (тот же принцип, что
в пакете U: афордансы под контролем состояния, а не среды).

## §6. Варианты

### V1 — «Зум-иммунитет» (рекомендуется, маленький пакет)
Политика: браузер страницы не зумит НИГДЕ и НИКАК; зум мира — только игровой.
- CSS: `html { touch-action: manipulation }` — double-tap умирает глобально
  (пересечение по цепочке).
- CSS точечно: несскроллящиеся панели (`#bottom-panel`, `#topbar`, `#minimap-box`,
  `#panel-ctl`, `.hint`, `#sel-info`) → `touch-action: none`; скролл-области
  (`.overlay-box.wide`, `#brief-text`, панельные скроллы, меню) → `touch-action:
  pan-y` (скролл жив, пинч закрыт).
- JS: `document.addEventListener('gesturestart'|'gesturechange', preventDefault)`
  — iOS-пинч (единственный надёжный способ на Safari), с гвардией «только когда
  игра на экране», чтобы не трогать системные жесты в меню-скроллах… точнее:
  gesturestart не нужен скроллам — он про пинч; блокируется всегда.
- Meta: `maximum-scale=1, user-scalable=no` — Android-страхование (iOS игнорирует).
- Объём: ~20–30 строк CSS + ~8 строк JS + 1 строка meta. Риск: минимальный,
  единственная точка регресса — нативный скролл меню (покрывается тестом).

### V2 — V1 + visualViewport-устойчивость (следующий пакет)
Даже при V1 остаются **неблокируемые вебом** зумы: системный iOS Zoom (трёхпальцевый)
и принудительный AA-зум Safari. Подписка на `visualViewport` resize/scroll: при
`scale > 1.01` канвас и HUD следуют за видимой областью (позиция/размер по
offsetLeft/Top/width/height), игра остаётся играбельной; одноразовый тост
«Масштаб страницы изменён — верните обычный масштаб жестом щипка в системных
настройках» / авто-выход. Объём: ~80–120 строк + тесты на двух контекстах.
Рекомендация: отдельным пакетом сразу после V1 — это и есть «уметь управлять
состояниями экрана», продолжение линии пакета U.

### V3 — сейв-система + аварийная перезагрузка (идея владельца)
Полноценные сейвы партии (сериализация состояния) — ценный продуктовый трек
(пауза-меню: Сохранить/Загрузить), но большой и с собственным аудитом; от зума
лечит косвенно. Дешёвая часть — кнопка «Перезагрузить экран» (`location.reload()`)
в меню «Ещё» как аварийный люк на случай непознанных состояний (в т.ч. системный
iOS-зум до готовности V2): 5 строк, прогресс миссии теряется — честно предупредить
в подтверждении.

### Сравнение

| Критерий | V1 | V2 | V3 |
|---|---|---|---|
| Убирает причину С1/С2 | да | да (+системный зум) | нет |
| Выход из «чужого» зума | зум невозможен | игра следует за экраном | reload (потеря прогресса) |
| Объём | XS (~30 строк) | M (~100 строк) | L (сейвы) / XS (кнопка) |
| Риск регресса | низкий (скролл меню) | средний (геометрия HUD) | низкий |
| Продуктовая ценность сама по себе | да | да | да (сейвы), нет (кнопка) |

## §7. Развилки владельцу (мои рекомендации)

- **Р1. Состав работ**: рекомендую **V1 сейчас** (пакет Q) → **V2 следующим
  пакетом** (R) → V3-сейвы отдельным треком по желанию. Альтернатива: V1+V2 одним
  пакетом (дольше до поставки, риск смешанных регрессов).
- **Р2. Meta-тег**: добавить `maximum-scale=1, user-scalable=no`? Рекомендую **да**
  (Android-страхование; iOS всё равно игнорирует; игровой зум сохраняет
  функциональность масштабирования).
- **Р3. Аварийная кнопка «Перезагрузить экран» в «Ещё»**: рекомендую **да** —
  дёшево, страхует системный iOS-зум до готовности V2 и любые непознанные кейсы.
- **Р4. Сейвы**: рекомендую **в бэклог** как отдельный продуктовый трек (не как
  костыль от зума).

## §8. План кода V1 (после выбора)

1. style.css: политика touch-action (html manipulation; панели none; скроллы pan-y).
2. index.html: meta `maximum-scale=1, user-scalable=no`.
3. js/input.js (или game.js): gesturestart/gesturechange preventDefault с комментарием.
4. Тесты: новый `scripts/v_verify.mjs` — инвариант «ни один видимый элемент не
   имеет цепочки, разрешающей double-tap или pinch» (расширение аудита из
   mobile_zoom_repro), живость скролла меню (scrollTop меняется), CDP-зум больше
   не должен возникать в принципе (meta на Android), скриншот-пара для отчёта.
   Расширение sim_touch (T17+: CSS-политика на `<html>`).
5. Регресс: check, smoke, 17 симов, audit_move, check_minimap_view, u_verify.
6. Версия **Q**, дата по правилу V, письмо Арене (дельта: style.css, index.html,
   input.js, тесты) — при её возвращении.
