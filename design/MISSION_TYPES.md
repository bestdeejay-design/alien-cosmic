# Типы миссий: глаголы, условия победы, перекраска кампании

> Автор: Z.ai. Опирается на `design/MISSIONS_AUDIT.md` (аудит Арены, b158f19)
> и замеры владельца. Статус: на утверждение владельцу; после утверждения
> M0 уходит Арене как ТЗ. Код в этой поставке не меняется.

## 0. Зачем этот документ

Аудит показал: на всю кампанию у игрока два макро-глагола — «снеси всё» (9
миссий) и «продержись» (5 миссий). Твисты Арены (§3 аудита) чинят середину
кампании дёшево, data-only. Но владелец ждёт большего: **развитие формата** —
несколько узнаваемых ТИПОВ миссий, как в классических RTS (WC3: достичь/
удержать/эскорт; SC2: спасение/гонка/босс). Этот документ добавляет систему
типов: минимум новых win-условий в движке — максимум новых форматов в кампании.

Принцип (из аудита, подтверждён владельцем): тип = **новый глагол +
ограничение + асимметрия**. Тип в коде = `objective` + модификаторы старта.
Никаких новых юнитов и систем ради типов.

## 1. Сводный диагноз (аудит + код)

- Глаголы: «уничтожьте все постройки» ×10, «продержитесь N минут» ×5.
  Обе макро-задачи решаются одной стратегией: окопаться → перекачаться → задавить.
- Карта — декорация: минералов с избытком (Н5), экспансия не нужна ни разу,
  снабжение не жмёт (Н6), туман не заставляет разведывать.
- Обороны можно выигрывать контратакой (Н1) — движок это разрешает, брифинги молчат.
- «Новинки» брифингов фиктивны: разблокировок по миссиям нет, танк строится с №0.
- Поле `medics` оборонных профилей мертво (Н4): волны без медиков всегда.
- Структурно уникальна только №8 (отряд без базы).

## 2. Типы миссий (7)

| Тип | Глагол игрока | Статус в движке | Референс |
|---|---|---|---|
| ШТУРМ | снеси всю базу | есть (bcount win) | №0, №6 |
| ОБОРОНА | продержись до события | есть (defense timer) | №1, №4, №9, №12 |
| ОТРЯД | выполни задачу малым отрядом | есть (noBase) | №8 |
| ЦЕЛЬ | уничтожь конкретный объект | **новое** (keyTarget) | №10, №14 |
| ОСАДА | возьми объект до дедлайна | **новое** (keyTarget + loseDeadline) | №2, №7, №11 |
| ЭКОНОМИКА | накопь/добудь раньше соперника | **новое** (stockpile) | №3 |
| ЭВАКУАЦИЯ | выведи выживших в зону | **новое** (evacZone) | №1-финал, №13-отход |

Модификаторы (приправы, не типы): `buildZone` (стройка только в своей зоне),
бедная карта (`rich`, без нейтралов), стартовый tech врага, профиль волны
(рейдеры/черепаха/бронированный кулак — из аудита), мортиры/медики в волнах.

Каждый тип отличим игроком за первые 30 секунд: другой экран задачи,
другая победная строка, другая минимап-метка.

## 3. Движковые добавления M0 (поставки Арены, одна поставка)

Малые, изолированные, каждое — с сим-тестом. Логика поражений не трогается,
кроме прямо описанного.

- **М1 `keyTarget`** — `ms.objective = { kind:'key', type:'cc'|..., name }`:
  победа при уничтожении помеченного здания противника. Рендер: маркер-ромб
  над зданием-целью (обе расы, токены DS) + точка на минимапе. В остальных
  режимах ничего не меняется. Если ключевых зданий несколько — побеждает
  уничтожение последнего из списка.
- **М2 `stockpile`** — `{ kind:'stockpile', amount }`: победа при накоплении
  `amount` эрга (счётчик принятого КЦ/гнездом минерала; если приём не
  централизован — счётчик при добыче, выбрать по коду и описать в поставке).
  Экран задачи показывает прогресс (собрано/нужно).
- **М3 `evacZone`** — `{ kind:'evac', x, y, r, need, hold }`: победа, когда
  `need` живых своих юнитов находятся в зоне `hold` секунд подряд; юнит
  «погружается» (исчезает, помечается `evacuated=true`, не считается
  погибшим в статистике). Совместимо с noBase.
- **М4 `loseDeadline`** — `{ deadline, label }`: в штурмовых/осадных миссиях
  по истечении таймера происходит событие из `defenseStep`-механизма
  (волна усиления врага; при `hard:true` — поражение). Таймер виден игроку.
- **М5 `buildZone`** — `ms.buildZone = [rects]`: `canPlace` для игрока
  разрешена только внутри зон (турели/стены/здания). Рендер: пунктирная
  граница зоны на земле. ИИ не ограничен.
- **М6 фикс Н4** — `defenseStep` читает `profile.medics`: волны получают
  медиков по профилю (№9: 4, №12: 5). Баг-фикс, не дизайн.
- **М7 честные «Новинки»** — текстовая правка брифингов: «Новинка: X»
  остаётся только там, где X реально впервые упоминается кампанией
  (гейтинг меню стройки — отдельная тема, в M0 не входит).
- **Тесты**: новый `scripts/sim_wins.mjs` — по сценарию win/lose на каждое
  условие (keyTarget: снос цели = win, снос всей базы без цели = прежний
  win; stockpile: порог = win; evacZone: N юнитов в зоне = win, выход из
  зоны сбрасывает hold; loseDeadline: таймер = волна/lose; buildZone:
  canPlace вне зоны = false). Весь существующий регресс обязателен.

## 4. Перекраска кампании (только конфиги миссий + тексты)

Совмещает типы (§2) и твисты Арены (§3 её аудита). Порядок кампании не
меняется, разблокировка последовательная.

| № | Тип | Что делаем |
|---|---|---|
| 0 | ШТУРМ | Туториал — не трогаем |
| 1 | ОБОРОНА → ЭВАКУАЦИЯ | После таймера — фаза «погрузи 6 юнитов в зону шаттлов» (М3); брифинг называет оба глагола |
| 2 | ОСАДА | Сердце гнезда = keyTarget (М1) + волна усиления по дедлайну (М4); профиль «рейдеры» из аудита (багги 8, танки 0) |
| 3 | ЭКОНОМИКА | Накопи 2500 эрга (М2) + открытая карта и плазмеры врага (аудит); волны давят, экономика решает |
| 4 | ОБОРОНА (короткая злая) | Твист аудита: prep 120, total 8:00, мортиры в волнах |
| 5 | ОБОРОНА + buildZone | Стройка только в пределах священных полей (М5) + мортиры (аудит); контратаку легализовать брифингом (Н1) |
| 6 | ШТУРМ (зеркалка) | Твист аудита: рейдеры по экономике; брифинг обыгрывает «свои против своих» |
| 7 | ОСАДА | Форт «Гвоздь» = keyTarget (М1) + контрбатарейная дуэль (аудит) |
| 8 | ОТРЯД | Эталон — не трогаем |
| 9 | ОБОРОНА | Самая отличная оборона — не трогаем; медики волн появятся сами (М6) |
| 10 | ЦЕЛЬ | «Сердце улья» = keyTarget с охранной фазой: сначала кольцо жвал, потом Сердце (текст + маркер) |
| 11 | ОСАДА-экономика | Бедная карта + черепаха (аудит) + дедлайн карательной волны (М4) |
| 12 | ОБОРОНА | Финал оборонной дуги — не трогаем; медики волн (М6) |
| 13 | ОТРЯД-диверсия | noBase: уничтожь объект «Око» (keyTarget в noBase) и выведи отряд в зону отхода (М3) |
| 14 | ЦЕЛЬ (финал) | Гнездо-крепость = keyTarget; ветераны врага (стартовый tech 1, аудит §14.2); брифинг называет обе фазы |

Итог: 7 типов на 15 миссий. Последовательность типов по кампании:
Ш · Об→Эв · Ос · Эко · Об · Об+Зона · Ш · Ос · От · Об · Ц · Ос · Об · От · Ц —
ни один формат не повторяется чаще двух раз подряд, у середины кампании
появляются три новых глагола.

## 5. Порядок работ

1. **M0** (Арена, одна поставка): М1–М7 + `sim_wins.mjs`. Без него типы не собрать.
2. **M1** (data-only, топ аудита): перекраска №3, №4.
3. **M2**: №2, №6, №7.
4. **M3**: №1, №5, №13 (используют М3/М5).
5. **M4**: №10, №11, №14.
По одной-две миссии за поставку, полный регресс Z.ai между поставками.
Пакеты A–D (бэклог владельца) идут параллельно своей очередью; пакет C
(размеры/разнообразие карт) усиливает типы и не блокируется ими.

## 6. Верификация Z.ai на каждую перекраску

- Прогон миссии в браузере: win-путь и lose-путь, скрины интро/старта/цели.
- Сим-тесты: sim_wins, smoke 15 миссий, существующие свиты — зелёные.
- Скрин победного экрана с новой победной строкой (язык обеих рас).
- Правка рукава «досрочной победы»: в оборонах контратака остаётся законной
  (Н1) — брифинг упоминает её как тактику, но не требование.

## 7. Что НЕ делаем

- Не вырезаем и не объединяем миссии: каркас 3 акта × 3 фракции × 3 биома держит сюжет.
- Не добавляем юнитов/систем ради типов (дроны/ЦК — из пакета D, отдельная очередь).
- Не делаем процедурную генерацию карт — ручные пресеты надёжнее и верифицируемее.
