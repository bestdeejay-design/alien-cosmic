# Сервер сохранения прогресса (примитив)

Учебный примитив по слову владельца (25.10.2026): «мы можем на трёх внешних
машинах развернуть БД для сохранения прогресса — научимся примитивно, потом
покажем Арене, чтобы она оптимизировала и внесла правки».

## Что это

- `save-server.mjs` — HTTP-сервер на node:http + node:sqlite (БД в одном файле
  `saves.db`). **Ноль зависимостей** — достаточно установленного Node ≥ 22.5.
- API: `GET /health`, `POST /api/save {player,key,value}`, `GET /api/load?player=&key=`,
  `GET /api/list?player=`. CORS открыт — игра может обращаться с любого стенда.
- Идентификация — **ник + пин** (решение владельца 25.10.2026): первый save под
  незанятым ником регистрирует его (пин хранится как SHA-256); все операции под
  ником требуют тот же пин, иначе 403. Без ника — анонимный случайный id
  (прогресс не ходит между машинами). Форма ввода — мини-оверлей в углу полигона.
- Клиент `r/save-client.js` в полигоне `/r/` синхронизирует ключи localStorage
  (`terranrts.progress` — прогресс кампании, `terranrts.quickBattle`): тянет при
  старте, толкает при изменении (раз в 20 секунд и при закрытии вкладки,
  dirty-guard против перетирания чужих записей).

## Обновление 25.10.2026 (Э6): капсулы и рейтинг

- **`GET /api/top?metric=raids|loot&n=100`** — рейтинг по серверному ключу
  `ac_stats` (его пишет `r/save-client.js` раз в 15 секунд). Отдаёт
  `{ok, metric, total, top:[{player, raids, loot, ccLevel, houseLevel, ts, rank}]}`.
- **`POST /api/grant {player, grant}`** — ручной подарок игроку (админка →
  «Игроки»). Кладёт запись в ключ `ac_grant` этого игрока; при входе полигон
  превращает её в legend-капсулу «раз в жизни». Если задан `ADMIN_PIN`,
  эндпоинт требует `Authorization: Bearer <ADMIN_PIN>`, иначе отвечает 401.
  **На публичном адресе `ADMIN_PIN` обязателен** — без него выдать подарок
  может любой.
- Конфиг капсул публикуется отдельным ключом `ac_chest_cfg` (админка →
  «Опубликовать на сервер»), локальная копия — в localStorage `ac_chest_cfg_v1`.
- Ключи полигона отделены от S1: `r.progress`, `r.quickBattle` (клиент читает
  старые имена для миграции), `ac_raid_session_v1`, `ac_stats`, `ac_grant`,
  `ac_chest_cfg`.

```bash
ADMIN_PIN=секрет PORT=8790 node server/save-server.mjs
curl 'http://127.0.0.1:8790/api/top?metric=raids&n=5'
curl -X POST http://127.0.0.1:8790/api/grant \
  -H 'Content-Type: application/json' -H 'Authorization: Bearer секрет' \
  -d '{"player":"BEST","grant":{"name":"Подарок администрации","rewards":[{"kind":"erg","params":{"amount":5000},"weight":1}]}}'
```

## Обновление 25.10.2026 (Э2): что починено после живой игры

- **Ник без регистра** — `BEST` / `best` / `BESt` теперь ОДИН профиль (было три, из-за
  этого «база пропала»). Канонический ник — первый введённый, пин проверяется от него.
- **Прокси `/api/*` в `server/static.mjs`** — страница и сохранения живут на одном
  origin, поэтому сейв работает на телефоне, при https и в предпросмотре (раньше клиент
  стучался на `http://<host>:8790`, что ломалось на https и на телефоне).
- **Режим полигона:** `POLYGON=1 PORT=8806 node server/static.mjs` — «/» отдаёт 302 на «/r/»,
  чтобы стенд с телефона открывался сразу в игре (относительные пути `r/index.html` при этом целы).
- **API:** добавлены `POST /api/delete` и `bytes` в `/api/list`; `POST /api/load` понимает
  и тело с пином, и `?pin=`; `version: 2` в `/health`.
- **Клиент** (`r/save-client.js`): синхронизирует три ключа (кампания, быстрый бой,
  **база рейда** `ac_raid_session_v1`), разрешает конфликты по времени сервера
  (не откатывает базу назад на второй машине), досылает `sendBeacon` при уходе,
  показывает статус/список/размеры сохранений в панели профиля (внутри КЦ).

## Обновление 27.10.2026 (P1/#45): вход поэтапно и защита от перебора

- **`POST /api/load {player, pin, key:"__check__"}`** — проверка профиля для шага 2
  пинпада: `200 {ok:false, error:"not found"}` = пин верный (ключа `__check__` нет),
  `403` = ник занят другим пином, `429` = кулдаун. Клиент (`r/save-client.js`,
  функция `loginWithPin`) отличает «неверный пин» от «сервера нет» именно по коду.
- **Rate-limit (П-5):** 5 неудачных попыток → кулдаун **60 с**, каждая следующая
  серия удваивает ожидание (60 → 120 → 240 … до 1 часа). Счёт **только по нику**
  (итерация 2 ревью: за прокси/туннелем адрес общий, пара «ник + адрес» давала
  обход сменой адреса); адрес остаётся в логе для диагностики. Успешный вход
  серию сбрасывает. Ответ `429` несёт `Retry-After`, инцидент пишется в лог
  строкой `rate-limit: …`.
- **`registered: true`** в ответе `/api/load` — сервер только что закрепил пин
  за ником; клиент показывает тост «Профиль создан».
  То же правило в `server/lovii-save-server.mjs` (постоянная БД владельца).
- **`version` в `/health`:** `save-server.mjs` → `3`, `lovii-save-server.mjs` → `5`.
- **Выход из профиля** (клиент) теперь чистит все локальные ключи профиля и базы —
  данные не остаются чужому человеку в браузере.

## Запуск на любой из трёх машин (chuwi / lovii / fonotext)

```bash
node server/save-server.mjs            # порт 8790, БД ./server/saves.db
PORT=9000 node server/save-server.mjs  # другой порт
TOKEN=секрет node server/save-server.mjs  # включить проверку Bearer-токена
```

Проверка: `curl http://localhost:8790/health`

Клиент полигона ищет API так: сначала **тот же origin** `/api/*` (для этого запускайте
статику через `PORT=8805 node server/static.mjs` — она проксирует `/api` на `127.0.0.1:8790`),
и только если прокси нет — прямой `http://<хост страницы>:8790`.
Для отдельной машины-БД задайте `API_PORT`/`API_HOST` при запуске статики:

```bash
PORT=8805 API_HOST=192.168.1.50 API_PORT=8790 node server/static.mjs
```

## Что передать Арене на оптимизацию

1. Формат: сейчас value — строка localStorage целиком; нужен версионированный
   DTO сейва (schemaVersion, как в R0-a captureHomeBaseDTO).
2. Идентификация: ник+пин уже работает; нужен нормальный профиль (смена пина, восстановление, не хранить пин в localStorage открытым текстом).
3. Стратегия: pull-once/push-20s — нужен разрешение конфликтов (last-write-wins
   с ts — потеряет изменения с двух машин).
4. Безопасность: CORS *, опциональный Bearer — нужен настоящая модель доступа.
5. Транспорт: HTTP + polling — на R1 заменить на API+DB вертикали (см. ресерч
   мультиплеера, фаза R1).
