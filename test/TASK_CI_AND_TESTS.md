# TASK — CI и единый раннер для проверок Alien Cosmic

> Задание для агентов, работающих над проектом. Документ самодостаточен: всё, что нужно,
> есть в этом репозитории. Пиши по-русски, код и комментарии — тоже по-русски (так принято в репо).
>
> **Порядок работы обязателен:** сначала — план и вопросы владельцу (комментарием в задаче или
> в `design/<AGENT>_MAILBOX.md`), дождаться ответа, только потом код. Без подтверждения план
> не реализуется.

---

## 1. Проект и стек

- **Alien Cosmic** — браузерная RTS: чистый JavaScript (ES-модули, **без сборки, фреймворков и
  внешних ассетов**), Canvas 2D, Web Audio. Один статический сайт (GitHub Pages).
- Логика — фиксированный шаг **30 Гц** (`LOGIC_DT = 1/30`), рендер — rAF с интерполяцией.
- Архитектура и контракты: [`ARCHITECTURE.md`](ARCHITECTURE.md). План развития:
  [`ROADMAP.md`](ROADMAP.md).

## 2. Что уже есть (факты, проверено по дереву `main`)

- `scripts/check.mjs` — статический чекер: синтаксис модулей, импорты↔экспорты, ссылки из
  `index.html`, запреты (`fetch`/XHR/WebSocket, абсолютные пути, внешние URL).
- `scripts/smoke.mjs` + `scripts/harness.mjs` — headless-прогон всей игры: стабы DOM/Canvas/Audio,
  реальный `js/game.js`, все миссии и скирмиш, проверка финала, перф-замер.
- **17** `scripts/sim_*.mjs` — точечные headless-симуляции на настоящем коде: движение, добыча,
  стройка, ремонт, туман, экономика, UI-панели, тач, i18n и т.д.
- `scripts/repro_stuck.mjs` — регрессия застреваний T1–T4 (playwright).
- Всего в `scripts/` — **66 файлов** (было 62 на момент kickoff), включая одноразовые `ac_*` и `scripts/shots/`.
- `scripts/gh_issues_seed.py` — посев задач в GitHub Issues (пакет Q, 22.10), скоуп `repo`.
- `scripts/gh_board_setup.py` — создаёт **GitHub Projects V2** «Alien Cosmic — задачи» с русскими
  статусами (Бэклог / К работе / В работе / На проверке / Ждёт / Готово), добавляет все issues,
  расставляет статусы по маппингу и прописывает правила в readme борда. Идемпотентен, требует
  токен со скоупом `project`.

**Про доски.** В проекте уже есть своя доска (Projects V2 через `gh_board_setup.py`). Отдельный
`agent-hub` из другого репозитория её не заменяет и не дублирует: здесь — Issues + Projects,
там — только протокол отчётов агентов. Вторую доску не заводить.

**Чего нет:** ни `.github/` (0 файлов), ни `package.json`. То есть ни один из этих прогонов не
запускается автоматически: проверки держатся на памяти человека.

## 3. Проблема

1. **Проверки необязательны.** Регресс попадает в `main`, если забыл руками прогнать 17 симов.
   В `ROADMAP.md` это уже видно: правки идут «после отчёта владельца», то есть баг сначала
   находит человек.
2. **Нет одной команды.** Новичок (человек или агент) не знает, что и в каком порядке запускать.
3. **`scripts/` превратился в свалку.** 66 файлов (на kickoff было 62): симы, проверки, одноразовые браузерные прогоны и
   генераторы скриншотов лежат в одной папке. Непонятно, что поддерживается, а что историческое.

## 4. Задача

### Ф1 (P1) — единый раннер

Сделать `scripts/test.mjs` — последовательный прогон с итогом и корректным кодом выхода:

1. `check.mjs` (статический анализ);
2. `smoke.mjs` (игра целиком);
3. все `sim_*.mjs` — по одному, последовательно, с таймаутом на каждый;
4. `repro_stuck.mjs` — **не включать** в обязательный прогон (нужен playwright и браузер),
   но предусмотреть флаг `--with-browser`.

Требования:

- вывод: одна строка на скрипт (`PASS`/`FAIL` + длительность), затем сводка
  `итого: N ok, M fail, T секунд`;
- код выхода `0` только если всё зелёное; иначе `1` и список упавших;
- `--only=sim_move,smoke` — запуск подмножества;
- `--verbose` — пробрасывать полный вывод;
- **никаких новых зависимостей**: только `node:` и то, что уже есть в репозитории.

Опционально (если не спорит с «без сборки»): `package.json` **без зависимостей**, только
`"scripts": { "test": "node scripts/test.mjs", "check": "node scripts/check.mjs" }`
и `"engines": { "node": ">=22" }`. Если владелец против `package.json` — раннер остаётся
единственной точкой входа, это допустимо.

### Ф2 (P1) — CI на GitHub Actions

`.github/workflows/ci.yml`:

- триггеры: `push` в `main`, `pull_request`, `workflow_dispatch`;
- `runs-on: ubuntu-latest`, `actions/setup-node` с Node 22;
- шаг: `node scripts/test.mjs` (или `npm test`, если появился `package.json`);
- таймаут job — 15 минут; лог прогона — в артефакт;
- **без секретов и без внешних сервисов**. `repro_stuck.mjs` в CI не запускать.

Критерий: PR с заведомо сломанным утверждением в любом симе — красный; чистый `main` — зелёный.

### Ф3 (P2) — порядок в `scripts/`

Разложить по назначению, не меняя содержимого скриптов:

```
scripts/
  test.mjs            — единая точка входа (Ф1)
  check.mjs
  smoke.mjs
  harness.mjs
  sim/                — все sim_*.mjs
  verify/             — verify_*.mjs, *_verify.mjs, audit_move.mjs
  shots/              — как есть
  ops/                — gh_issues_seed.py, gh_board_setup.py (доска и посев задач)
  oneoff/             — ac_*, touch_*, mobile_zoom_repro.mjs и прочие одноразовые
```

После переноса — обновить пути в документации, где они упоминаются (`README.md`,
`ROADMAP.md`, комментарии в самих скриптах: там указано `Запуск: node scripts/sim_move.mjs`).

## 5. Контракты, которые нельзя ломать

- **Приказы — данные** (`unit.order`: `move`, `attackMove`, `attack`, `gather`, `build`, `repair`,
  `garrison`). Это фундамент реплеев и сети — структуру не менять.
- `LOGIC_DT = 1/30`, фиксированный шаг; рендер интерполирует `prevX/prevY → x/y`.
- **Pathfinding API**: `findPath`, `hasLos`, `smoothPath`, `pathToPoint`, `pathToRect`,
  `nearestFreeTileAround`, `distToRectPx`. Расширять можно, менять сигнатуры — нет.
- `drawUnit(ctx, u, rx, ry)` — контракт рисования (нос по +X, `translate`/`rotate` уже сделаны).
- Баланс — только в `config.js`; в этой задаче его не трогать.
- Ноль внешних зависимостей в рантайме.

## 6. Границы задачи

- **Не менять `js/*.js`** в рамках Ф1–Ф3. Если прогон выявил баг — отдельная задача и отдельный PR
  со ссылкой на падающий тест.
- Не переписывать существующие симы и не «улучшать» их утверждения под зелёный результат.
- Не тащить Jest/Vitest/Playwright в обязательный прогон.
- Не трогать `design/shots/` и не добавлять новые бинарные файлы в репозиторий.
- **Не менять** `scripts/gh_issues_seed.py` и `scripts/gh_board_setup.py` по существу: только
  перенос в `ops/` в рамках Ф3. Они управляют доской и посевом задач.
- Токен не должен попадать в коммит, лог или артефакт CI. Чтение токена из `git remote` —
  известное слабое место (токен лежит в `.git/config`); отдельная задача — перейти на
  `gh auth token` или переменную окружения. В рамках этой задачи не переписывать.

## 7. Критерий приёмки

- [ ] `node scripts/test.mjs` на чистом `main` завершается кодом `0`, печатает сводку и укладывается
      в 5 минут (без `--with-browser`).
- [ ] Искусственно сломанное утверждение в одном симе даёт код `1` и имя упавшего скрипта
      (проверить и откатить).
- [ ] `--only=` и `--verbose` работают; неизвестный флаг — понятная ошибка, код `2`.
- [ ] CI зелёный на PR и красный на PR со сломанным тестом (ссылки на оба прогона — в отчёте).
- [ ] Ф3: в `scripts/` остались только точки входа, остальное разложено; ссылки в документации
      обновлены; `git grep "scripts/sim_"` не показывает битых путей.
- [ ] Ни одного нового рантайм- или dev-пакета (кроме опционального `package.json` без зависимостей).

## 8. Формат отчёта агента

1. **Резюме** — ≤10 строк: что сделано, что проверено.
2. **Изменённые файлы** — список с назначением каждого.
3. **Проверки** — команды, код выхода, ключевые строки вывода (не «всё работает», а факты).
4. **Расхождения с заданием** — отдельным пунктом, если были.
5. **Что не сделано и почему** — честно, без «потом доделаю».
6. **Риски** — что может сломаться у владельца при следующем запуске.

## 9. Ручной чек-лист владельца

1. `node scripts/test.mjs` — видно сводку, время, ни одного `FAIL`.
2. Сломать один сим (например, ожидаемое число юнитов) → прогон краснеет и называет скрипт.
3. Открыть PR → во вкладке Actions виден прогон; после merge в `main` — тоже.
4. Запустить игру как раньше (`python3 -m http.server 8080`) — геймплей не изменился.

## 10. Связанные решения

| Вопрос | Решение |
|---|---|
| Какая доска основная | **GitHub Projects V2 в этом репозитории** (`gh_board_setup.py`). Статусы: Бэклог / К работе / В работе / На проверке / Ждёт / Готово |
| Нужен ли `agent-hub` | Нет для этого проекта: он про протокол отчётов агентов, а не про доску задач |
| Откуда запускать проверки | `node scripts/test.mjs` — единственная точка входа (Ф1), в CI — она же (Ф2) |
| Где хранить одноразовые скрипты | `scripts/oneoff/`, чтобы `scripts/` не разрастался |
