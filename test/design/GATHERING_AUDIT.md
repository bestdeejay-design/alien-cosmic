## 1. Добыча кристаллов

### 1.1 Как воркер выбирает кристалл
Единая точка выбора — `nearestCrystal(st, u, exclude)` (`js/units.js:347-360`). «Занятости» кристаллов не существует: для каждого кристалла считается количество своих воркеров, уже ordered на него, и к дистанции добавляется мягкий штраф `crowd * TILE * 2.2` (≈70 px за каждого воркера):

```js
if ((o.kind === 'gather' && o.target === c) ||
    (o.kind === 'build' && o.resume === c)) crowd++;
...
const d = Math.hypot(c.x - u.x, c.y - u.y) + crowd * TILE * 2.2;   // js/units.js:355-358
```

Это смещение, а не фильтр: несколько воркеров спокойно сходятся на один кристалл. Все пути назначения сбора проходят через эту функцию:
- авто-сбор нового воркера — `spawnUnit` (`js/units.js:335-342`);
- возврат к сбору после постройки/стопа — `resumeGather` (`js/units.js:276-282`);
- перевыбор при исчерпании кристалла (`js/units.js:844-847`);
- failover после 4 неудач поиска пути (`js/units.js:867-872`);
- точка сбора здания на кристалле (`js/buildings.js:290`).

### 1.2 Остаток ресурса
Остаток существует и списывается, но игроку не показывается:
- кристалл: `{kind:'mineral', tx, ty, x, y, amount, max: amount, dead}` — `addCrystal` (`js/map.js:102-110`);
- списание при добыче: `c.amount -= take; if (c.amount <= 0) st.map.removeCrystal(c)` (`js/units.js:887-890`), удаление — `js/map.js:112-117`;
- единственная визуализация остатка — масштаб спрайта: `const s = 0.45 + 0.55 * (c.amount / c.max)` (`js/game.js:1166`), т.е. кристалл «тает»;
- числового показа нет нигде: кристалл нельзя выделить (`js/input.js:210-218` выбирает только юнитов, затем здания), тултипа нет, на миникарте — фиксированная точка 3×3, пока `amount > 0` (`js/ui.js:973-977`); в HUD — только общий банк (`res-minerals`, `js/ui.js:634`).

### 1.3 Ручной приказ и «рой»
Ручной ПКМ по кристаллу отправляет **всех** выделенных воркеров на один и тот же кристалл (`js/game.js:587-590` — per-unit цикл `orderGather(st, u, crystal)`). Лимита воркеров на кристалл нет; фаза добычи — таймер без проверки занятости (`js/units.js:880-895`). Автоназначенные воркеры (спавн/ралли/после постройки) распределяются приемлемо за счёт штрафа из §1.1; ручная группа — нет.

### 1.4 Месторождение как группа
Группировки нет: `st.map.crystals` — плоский массив независимых сущностей (`js/map.js:52`). Кластеры возникают только при генерации: `field(cx, cy, offs, amount)` штампует 8 тайлов вокруг главной базы (1350 × `rich`) и 6 у нейтральных расширений (950) — `js/map.js:152-171`, — но знание о группах нигде не сохраняется.

### 1.5 Параметры цикла
- `MINERAL_PER_TRIP = 8`, `MINE_TIME = 1.8` c (`js/config.js:24-25`);
- машина фаз `toMineral → mining → toDrop` — `updateGather` (`js/units.js:837-930`), искры/звук при ударе (`js/units.js:884-885`);
- сдача — ближайший достроенный КЦ своей стороны, отдельного перерабатывающего здания нет; радиус сдачи `TILE * 0.9`, всплывает `+8` (`js/units.js:897-919`);
- переносимый осколок на спине воркера — `js/units.js:2078-2086`.

## 5. Оценка перехода на «свободный кристалл» (для F.1)

**Вариант A — производный кап (рекомендован):**
1. При генерации проставлять `fieldId` кристаллам (`js/map.js:102-110`, ид передавать в `field()` — `js/map.js:152-171`); `removeCrystal` менять не нужно.
2. `nearestCrystal` — из мягкого штрафа сделать жёсткий выбор: «ближайший свободный (`crowd < LIMIT`, напр. 1–2) в ближайшем непустом месторождении → фолбэк любой свободный → фолбедельник наименее людный».
3. Объём: `map.js` ≈ +5 строк, `units.js` ≈ +25–40 строк. UI не обязателен, но дешёвое продолжение — показ `amount` в тултипе/панели (см. §1.2).

**Вариант B — истинные резервации** `c.claims`: точнее, но клейм надо вести во всех точках мутации ордера — `orderGather` (`js/units.js:238-244`), `orderStop` (`292-298`), свопы resume в `orderBuild/orderRepair` (`249-264`), смерть воркера, исчерпание цели (`882`). Риск утечек клеймов; выигрыш по производительности в текущих масштабах не нужен.

**Открытые продуктовые вопросы (в дизайн-док Арены):**
- семантика ручного ПКМ (`js/game.js:587-590`): стек на занятый кристалл разрешён или выделение раскидывается по месторождению;
- лимит на кристалл (1 или 2) и плотность месторождений после его введения;
- показ остатка: тултип при наведении, панель при выделении, число на миникарте.

**Производительность:** не проблема — `nearestCrystal` O(кристаллы × воркеры) на вызов при ~12 воркерах и ~40 кристаллах.

**Регресс-идея:** в `scripts/sim_*.mjs` — заспавнить 8 воркеров, assert «на одном кристалле никогда ≤2».
