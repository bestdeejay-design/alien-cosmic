## §1. Репорт владельца (22.10.2026, скрин с живой игры 14:02)

> «когда выбираешь в панельке при строительстве что-то — показывается сообщение
> с описанием юнита, например. Оно не уходит долго, или совсем не уходит.
> Проверь, как это должно работать и почему на мобилке оно не уходит и висит, мешает»

На скрине: тап по кнопке «Рейнджер 50» в панели казармы → над панелью карточка
`#cmd-tip`: заголовок «Рейнджер 50», описание «Экипирован плазменным карабином…»,
строки статов (жизнь 52 · урон 7 · радиус 134 · население 1 · подготовка 13 с).
Карточка перекрывает мир и висит после того, как команда уже выполнена.

## §2. Как это устроено (механика)

Тултип `#cmd-tip` — один элемент на `document.body` (не внутри кнопки),
общий для: кнопок команд (`buildCmdGrid`, ui.js:1593–1617), чипов очереди
(`buildQueueButton`, ui.js:1870–1890) и эргономического тултипа кристалла
(F.1, `updateCrystalTip`).

**Пути ПОКАЗА** (ui.js:1605–1610, 1872–1876):
- `mouseenter` — десктоп-наведение;
- `focus` — клавиатура/программный фокус;
- `pointerdown` с `pointerType === 'touch'` — намеренный мобильный «пик»:
  на таче наведения нет, поэтому описание показывается по касанию.

**Пути СКРЫТИЯ** (ui.js:1611–1614, 1877–1880, 1603, 1889):
- `mouseleave` — курсор ушёл с кнопки (с гвардией по фокусу);
- `blur` — кнопка потеряла фокус;
- успешный `click` команды → `c.on()` + `hideTip()` (побочный эффект);
- `updateCrystalTip`: курсор ушёл с кристалла → `hideTip()` (input.js:256 —
  вызывается ТОЛЬКО из mousemove канваса).

**Пересборка панели**: `update(game)` (ui.js:1300) гоняется каждый кадр; при
смене сигнатуры (`sig` — состав выделения + очередь здания, ui.js:1325–1331)
вызывается `rebuildPanel` → `els.cmdGrid.innerHTML = ''` — все кнопки и чипы
уничтожаются и создаются заново. Сигнатура меняется при каждом событии
производства (юнит встал в очередь / вышел) — панель казармы с живой очередью
пересобляется регулярно. Сама пересборка тултип НЕ гасит: он на `body`,
а не в сетке.

## §3. Корень: на таче у показа нет парного скрытия

Дизайн тултипа — **hover-артефакт**: живёт, пока курсор на кнопке. Для тача
добавили только ПОЛОВИНУ жизненного цикла (показ по pointerdown), а скрывающую
половину не построили:

1. Нет `pointerup`/`pointercancel` — тап «отпустили», а тултип остаётся.
2. Нет таймера авто-скрытия — ни одного `setTimeout` на `tipEl` (есть только
   280-мс `blocked-feedback` на кнопке).
3. Нет скрытия по тапу мимо — ни одного глобального слушателя.
4. `mouseleave` на таче не приходит физически (курсора нет).
5. `blur` на iOS не приходит: Safari не даёт кнопкам фокус по тапу; на Android
   фокус есть, но `blur` приходит только при переводе фокуда — не гарантия.
6. Единственное «спасение» — побочный эффект следующего УСПЕШНОГО клика по
   команде (`hideTip()` в обработчиках click). Отсюда «не уходит долго»: висит
   до следующего удачного тапа где-то в панели.
7. Тап по НЕДОСТУПНОЙ команде (очередь полна 5/5, мало минералов, лаборатория
   занята, нужен Штаб-2): click → `blockedFeedback` + `showTip(…, reason)`
   (ui.js:1596–1599) — тултип показан с причиной, и для него НЕТ НИ ОДНОГО
   пути скрытия. Отсюда «совсем не уходит».
8. Ускоритель: если кнопка успела пересобраться, пока палец ещё на экране
   (очередь сдвинулась), `click` по уничтоженной кнопке не приходит вообще —
   показ был, скрытия не будет.

**Семейство**: эрготултип кристалла (F.1) на таче не показывается (живёт на
mousemove), но и его путь скрытия на таче мёртв — тот же класс дефекта,
закрывается той же правкой.

## §4. Как это должно работать

- **Десктоп** — текущее поведение корректно: тултип = артефакт наведения,
  исчезает вместе с курсором/фокусом/выполнением команды. Ничего не меняем.
- **Тач** — «пик» по касанию сохранить (это единственный способ посмотреть
  описание до покупки), но показать его ТРАНЗИЕНТНЫМ: само уходит по таймеру,
  мгновенно уходит по следующему тапу где угодно, не переживает пересборку
  панели. Тултип никогда не живёт «вечно» по определению.

## §5. Варианты

### П1 — «честный пик» (рекомендуется)
Полный жизненный цикл тач-показа:
- авто-скрытие через 5 с (читать описание + статы успеваешь; таймер
  перезапускается каждым новым показом);
- мгновенное скрытие по следующему `pointerdown` в документе (capture-фаза,
  цель-исключение — сама кнопка, вызвавшая показ);
- скрытие в `rebuildPanel` (смена выделения/очереди = старое описание
  неактуально) и при старте placement;
- работает и для disabled-тапа с причиной — «висящих причин» больше нет.
Объём: ~30–40 строк в ui.js + 1 блок в sim_touch + 2 блока в v_verify.
Риск: низкий — десктопные пути не тронуты (вся логика под флагом
touch-показа).

### П2 — только таймер
Авто-скрытие 5 с на touch-показах, больше ничего. ~8 строк.
Минус: до 5 секунд после КАЖДОГО тапа карточка всё ещё висит и перекрывает
мир, если пользователь уже пошёл играть дальше.

### П3 — убрать тач-показ
Удалить pointerdown-ветку. Самый короткий дифф, но на мобилке описание
юнита посмотреть станет негде — потеря фичи, введённой намеренно.
Отклоняю, привожу для полноты.
