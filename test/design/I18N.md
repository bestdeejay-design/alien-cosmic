# I — i18n: английский и каркас локалей (дизайн утверждён владельцем)

Автор: Arena · 2026-10-20 · статус: **владелец утвердил направление и решения; I-код разрешён**.
База сверки: принятые H + hotfix K (`main` 63c9f8d; текущая ветка
`arena/3e494e43-alien-cosmic`). Сиды, миссии и условия победы остаются вне
локализации; русские исходники документов сохраняются.

## 0. Решение в одном абзаце

Утверждён общий слой `js/i18n.js` и полные словари `locales/ru.js` /
`locales/en.js`: короткие ключи в UI и коде, полный текст — в языковых файлах,
русский fallback, плейсхолдеры `{n}` вместо склейки и plural forms. Переключатель
на главном экране показывает явно зарегистрированные локали. При первом запуске
выбирается первая поддерживаемая локаль из `navigator.languages` (сначала
точное совпадение, затем базовый код), иначе `ru`; сохранённый допустимый выбор
имеет приоритет. Настройка хранится в `terranrts.language` и не затрагивает
сейв кампании.

## 0.1 Принцип английской локализации

Указание владельца: перевод — **творческая адаптация, не дословный перевод**.
Цель — чтобы англоязычный игрок так же погружался в мир: передать атмосферу,
сюжет и чувство приключения, а не копировать русские обороты и порядок слов.

- Синтаксис, ритм, идиомы и метафоры можно перестраивать ради естественного
  выразительного английского; сохранять смысл, эмоциональный эффект и разные
  голоса мира.
- В брифингах, CODEX, репликах/тостах и эпилогах беречь напряжение, интригу,
  ставки и атмосферу исследования; не терять важные намёки и не добавлять
  спойлеры, которых нет в исходнике.
- Не придумывать факты, мотивы, события и детали канона; не менять
  хронологию, причинность, цель/условие миссии или то, что игрок должен понять
  и сделать. Утверждённые имена и термины из глоссария остаются стабильными.
- Нарративный текст может быть образным; кнопки, цели, предупреждения,
  подсказки и инструкции должны оставаться краткими и однозначными. Не жертвовать
  понятностью игрового действия ради красивой формулировки.
- Сохранять различимые регистры фракций: Helios — военный/инженерный;
  Kharid — органический/песенный. Оценивать EN не только построчно, но и как
  цельный игровой опыт: текст должен вовлекать игрока в историю и приключение.

текстовых полей/узлов в источнике, а не итоговое число уникальных ключей:
повторы вроде имени главы будут нормализованы, а динамические шаблоны ниже
добавят отдельные ключи.

### Что именно включить в реестр

- **Статический HTML:** `title`, `meta description`, `lang`, названия кнопок,
  подсказки `title`, статические абзацы помощи, подписи размеров/формы, версия.
  Чистые брендовые знаки `ALIEN COSMIC`/`RTS`, числа пресетов `48/64/80/96`,
  время-счётчики и символы клавиш не переводятся.
- **Динамический UI:** панели команд, очередь/производство/исследование,
  гарнизон, состояние юнита, недостижимый путь, таймер очереди, HP/характеристики,
  панель кристалла, карточки и брифинги, заблокированные главы, тосты, победа,
  поражение, статистика, пауза/звук/выход/сброс.
- **Игровые данные с текстом:** два облика каждого юнита/здания/улучшения;
  все сообщения `STR` у Гелиоса и кхарида; все 19 миссий и быстрый бой;
  `CODEX` и его прогрессные записи; учебные подсказки и сезонная плитка
  «Сезон 2 · СКОРО».
- **Не переводить:** внутренние `id` (`worker`, `scout`, `cc`…), имена полей,
  enum-приказы, `mission.id`, seeds, карты, числа баланса, localStorage-ключи,
  клавиши/семантику команд, комментарии и developer console. Ни одно условие
  миссии или игровая формула не меняется ради английской версии.

## 2. Архитектура

### 2.1 Файлы и владение строками

- `js/i18n.js` — выбор locale, `t(key, params)`, фолбэк на `ru`, интерполяция,
  форматирование числа/даты, безопасное обновление статического DOM.
- `locales/ru.js`, `locales/en.js` — **одна и та же схема**, все видимые строки
  каждого языка; код содержит ключи, а не русский/английский текст.
- В словаре — разделы `ui`, `hud`, `factions`, `units`, `buildings`, `upgrades`,
  `messages`, `codex`, `missions`, `skirmish`, `terms`.
- Ключи стабильны и семантичны, не строятся из переведённого текста. Сущности
  адресуются по существующим ID; mission content — по `mission.id`, а не по
  номеру элемента массива (у бонусных глав ID имеет разрыв).

Эскиз схемы (не финальный полный экспорт):

```js
{
  meta: { code: 'en', label: 'English', htmlLang: 'en' },
  ui: { menu: { season1: 'Season 1 · Campaign' } },
  factions: { human: { name: 'HELIOS' }, alien: { name: 'KHARID' } },
  units: {
    scout: {
      human: { name: 'Pathfinder', description: '...' },
      alien: { name: 'Listener', description: '...' },
    },
  },
  messages: {
    underAttack: {
      human: 'Base under attack!',
      alien: 'The brood is under attack!',
    },
  },
  missions: {
    19: { name: 'The Long Night', briefing: ['...', '...'] },
  },
}
```

### 2.2 API и шаблоны

- Обычная строка: `t('ui.menu.season1')`.
- Динамическая: `t('ui.quickStart', { mission: n })`, словарь содержит
  `Quick start — mission {mission}`.
- Сообщение фракции: тон остаётся раздельным в обеих локалях,
  `message('underAttack', faction)` → соответствующий вариант.
- Имена/описания: `entityText('unit', type, faction, 'name|description')`;
  `config.js` после извлечения хранит баланс/ID, а не `hname/aname/hdesc/adesc`.
- Цель: `objectiveLabel(mission)` выбирает `missions[mission.id]` и шаблон по
  неизменному `objective.kind`; значения (`amount`, `need`, `deadline`) передаются
  как параметры. Механическая структура `MISSIONS` остаётся источником истины.
- Счётные формы (`1 unit`, `2 units`; русские формы 1/2/5) хранятся в вариантах
  `one/few/many/other` и выбираются через `Intl.PluralRules`; числа/даты — через
  `Intl.NumberFormat` / `Intl.DateTimeFormat`. Ни `label + count`, ни склейки
  частей предложения.
- HTML-слова из CODEX/помощи не должны приходить из непроверенного HTML-словаря.
  Простые узлы получают `textContent`; форматированные абзацы — безопасные
  текстовые сегменты/разрешённые `strong`/переносы, созданные через DOM. При
  рефакторинге убрать прямую вставку переведённой строки через `innerHTML`.

### 2.3 DOM и выбор языка

- Для статического текста `index.html`: `data-i18n="ui.menu.season1"`,
  `data-i18n-title="ui.panel.hideTitle"` и аналогичные маркеры. `applyLocale()`
  переводит маркеры и обновляет `<html lang="…">`, `document.title` и meta
  description.
- Для созданных в JS карточек/тултипов/тостов — `t()` при рендере и
  `textContent`; никакой переводимый текст не остаётся в HTML-шаблонах.
- Язык выбирается **на главном экране** отдельным компактным `select` из всех
  явно зарегистрированных локалей; пользователь сначала выбирает язык, затем
  кампанию или быстрый бой.
- Ключ хранения: `terranrts.language`, отдельно от `terranrts.progress` и
  `terranrts.panel`. Допустимый сохранённый код всегда имеет приоритет. При первом
  запуске (или невалидном сохранённом коде) берётся первая поддерживаемая локаль
  из `navigator.languages`: сначала точное совпадение BCP-47, затем базовый код;
  если совпадения нет — `ru`. Ошибка чтения/записи localStorage не ломает загрузку.
  Смена языка без перезагрузки и без изменения игры/сейва; перерисовываются меню,
  подписи UI, подсказки и открытая карточка/кодекс.
- **Будущие локали — явный реестр:** `SUPPORTED_LOCALES` хранит безопасный код,
  подпись и importer каждого модуля. Только записи реестра видны в переключателе
  и могут быть импортированы; код для динамического импорта не строится из
  localStorage или `navigator.languages`. Новая локаль требует добавить
  `locales/<code>.js` и запись в реестр; `scripts/sim_i18n.mjs` автоматически
  проверит соответствие файлов и реестра, полноту ключей и placeholders.

### 2.4 Фолбэк и контроль полноты

`t(key)` сначала ищет значение в выбранной локали, затем в русском словаре;
если нет и там — отдаёт заметный `[missing:key]` в dev, а проверка падает.
Фолбэк — страховка релиза, не разрешение неполного EN: тест требует 1:1 ключи
ru/en и совпадающие `{placeholders}`. Любой новый UI-текст должен сначала
получить ключ в обеих локалях.

## 6. Тест-план и критерии приёмки

### 6.1 `scripts/sim_i18n.mjs`

- Рекурсивное покрытие: все модули, зарегистрированные в `SUPPORTED_LOCALES`,
  имеют одинаковую схему/типы и проверяются автоматически; `locales/*.js`
  должны в точности соответствовать реестру (нет незарегистрированных файлов
  или записей без модулей).
- Placeholder parity: наборы `{name}`/`{count}` совпадают по каждой паре ключей;
  рендер не оставляет незаменённых `{...}`.
- `t()` проверяется на RU, EN, неизвестную locale, отсутствующий EN-ключ
  (RU fallback), отсутствующий RU-ключ (явный missing-marker/ошибка теста),
  множественные формы 0/1/2/5/21 и формат чисел/даты.
- `localStorage` хранит только язык; поддерживаемый сохранённый код имеет
  приоритет, иначе первый поддерживаемый `navigator.languages` (exact, затем
  base), иначе `ru`. Invalid value и storage exception не ломают загрузку.
  Переключение не меняет `progress`, `panel` и состояние партии.
- Проверка статической разметки: каждый `data-i18n*` разрешается в обоих
  словарях; `document.documentElement.lang`, title и meta description меняются.
- Полнота сценариев: меню/Сезон 2 «СКОРО», карточки основных и бонусных миссий,
  брифинг, обе фракции, все 8 вкладок CODEX (закрытая/открытая), быстрый бой,
  panel/tip, очередь/исследование, минералы/снабжение, стокпайл/эвакуация/
  дедлайн, тревога/сирена, разведка, авторемонт, победа/поражение и эпилог.
- No-hardcode: в целевых runtime-файлах нет пользовательских RU/EN-литералов
  вне locale-модулей/явного списка кодов клавиш и технических имён. Проверка
  должна игнорировать комментарии/тестовые fixtures и ловить литералы, а не
  запрещать кириллицу в README.
- Инварианты кампании: все текущие миссии остаются на прежних `id`/порядке,
  прежние seeds/AI/пороги и win conditions остаются нетронутыми; уже существующие
  `sim_wins`, `sim_codex`, `sim_hq` продолжают проверять поведение.
- Интеграция в quality gate: `scripts/check.mjs` обязан запускать
  `scripts/sim_i18n.mjs` как дочернюю проверку и передавать её ненулевой exit code
  наверх. Поэтому обычный `node scripts/check.mjs` проверяет полноту/согласованность
  локалей; `sim_i18n.mjs` также можно запускать отдельно для быстрой отладки.

### 6.2 Регресс и ручная приёмка

На текущем H/K-снимке — 12 сим-наборов (`sim_build`, `sim_codex`, `sim_gather`,
`sim_grade`, `sim_hq`, `sim_move`, `sim_panel`, `sim_repair`, `sim_shell`,
`sim_traffic`, `sim_ux`, `sim_wins`), плюс `smoke`, `audit_move` и `check`.
В I `scripts/check.mjs` будет запускать `sim_i18n.mjs` как обязательную
вложенную проверку: полный регресс — **15 верхнеуровневых команд / 16 логических
наборов**. В стандартном регрессе не запускать `sim_i18n` второй раз отдельно;
прямой запуск остаётся доступен для быстрой отладки. Также: `node --check` для
`js/*.js` и `scripts/*.mjs`, `git diff --check`.

Ручной браузерный чек-лист (без игровых изменений):

1. На первом запуске выбрать первую поддерживаемую локаль из `navigator.languages`;
   при неподдерживаемом списке — RU. Проверить exact- и base-match. Все локали из
   реестра доступны в селекторе до входа в Сезон 1.
2. Валидный сохранённый выбор имеет приоритет над браузером после обновления;
   invalid value безопасно заменяется browser match/fallback RU. Прогресс, панель
   и состояние партии не сбрасываются при переключении.
3. Проверить меню, кампанию с 15 основными + 4 бонусными главами, брифинги,
   быстрый бой, CODEX; открыть закрытую и открытую запись, обе фракции.
4. В партии проверить динамические строки обоих сторон: supply/erg, цель и её
   счётчик, таймер обороны/дедлайн, очередь/грейд, ремонт, scout/contact,
   alarm, win/lose/epilogue. Ни одного случайного русского/английского хвоста.
5. Все названия из утверждённого глоссария совпадают в кнопках, подсказках,
   брифингах, кодексе и EN-вики; клавиши и их команды не меняются. Наративный
   английский звучит естественно и атмосферно, сохраняет интригу и голоса фракций,
   но не добавляет фактов и не затемняет цель миссии.
6. `pageerror`/ошибок консоли — 0; переключение языка не перезапускает бой.

**Условия «готово»:** полный EN без пропусков; схемы RU/EN и placeholders
совпадают; фолбэк работает; переключатель сохраняется; поддерживаемый язык
браузера выбирается при первом запуске, иначе RU;
регресс 15 верхнеуровневых команд / 16 логических наборов (включая
`sim_i18n.mjs` внутри `scripts/check.mjs`) + syntax/check зелёные;
`GAME_VERSION='I'`; ни один кампанийный seed/ID/объектив/порог/флаг не менялся.
