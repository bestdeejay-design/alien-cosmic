# Каталог визуальных компонентов — приёмочный лист дизайн-системы

> Назначение: приёмка переработки визуала (дизайн-система → компоненты).
> У каждого компонента есть ID и критерий приёмки. Ничего не считается
> «сделанным», пока не отмечены все строки его группы. Каталог — эталон
> полноты: если компонента нет в каталоге, но он виден в игре, он всё
> равно подлежит системе (добавить строку, не игнорировать).
>
> Источник карты кода: `render()` в `js/game.js:689`, `drawBuilding`
> `js/buildings.js:331`, `drawUnit` `js/units.js:1472`, `icon()`/`drawMinimap`
> `js/ui.js:24/744`, `buildTerrainCanvas` `js/map.js:292`, `paint` `js/fog.js:87`,
> DOM/оверлеи `index.html` + `style.css`.

## 10. Порядок приёмки (регламент)

1. **Система до компонентов**: сначала DS-1…DS-10 (токены и словарь), потом группы.
2. **Группы в порядке риска**: BD (здания — текущая боль) → IC (иконки) → UN (юниты — только сверка с эталоном `design/shots`) → E (эффекты) → W → H → T/TL → C.
3. **Каждая строка**: скриншот из `scripts/shots/shots_all.sh` + при необходимости живой прогон сцены. Лист против кода: `node scripts/check.mjs`, `audit_move.mjs` (A9/A10), `sim_move.mjs` — обязаны остаться зелёными.
4. **Регресс**: после каждого пакета правок — полный пересбор `design/shots/`, дифф с предыдущими листами (визуально или по хэшу).
5. **Запрещено**: править лист руками под код; компонент без критерия; «сделано» без скриншота.

## 11. Известные слабые места (входные данные для системы)

- **Здания v2** — владелец забраковал: плотность деталей ниже юнитов, часть силуэтов не читается. Ревизия в первую очередь.
- **Иконки IC-1…IC-5** — старый плоский стиль, не связаны с v2-языком юнитов/зданий.
- **Эффекты E-1…E-7** — простые круги/палки вне фракционных языков.
- **DOM/HUD** — функционален, но не подчинён токенам; типографика дефолтная.
- **Det-правило**: любые новые случайности в отрисовке — только рендерное время; в симуляцию не лезть (прогон srand-тестов обязателен).
