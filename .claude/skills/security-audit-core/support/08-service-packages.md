# Продаваемая услуга: пакеты, сроки, цена, приёмка

> Как упаковать проверку в услугу, которую покупают. Цены — **модель расчёта**, а не фиксированный
> прайс: считай по scope, а не «за страницу отчёта». Конкретные суммы согласовывай под рынок и издержки.

## 1. Пакеты

### Express Black (Black Box)

- **Для:** быстрый внешний взгляд перед релизом, лендинг/промо, нет доступа к коду.
- **Входит:** recon, карта поверхности, проверки снаружи, configuration review, отчёт + executive summary.
- **Не входит:** код, внутренние сервисы, social engineering, DDoS, retest (продаётся отдельно).
- **Срок:** 5–7 рабочих дней после подписания scope.
- **Результат:** «Снаружи видно вот это; внутри не проверяли» — честные ограничения в отчёте.

### Standard Grey (Grey Box) — основной пакет

- **Для:** игры и финтех с staging и тестовыми доступами. Рекомендуемый старт для большинства клиентов.
- **Входит:** всё из Express + threat model, тестовые роли, API/логика, экономика/платежи по домену,
  отчёт + план + **1 retest** в течение 30 дней после передачи исправлений.
- **Не входит:** полный код (White), продакшн-данные, social engineering, DDoS.
- **Срок:** 10–15 рабочих дней тестирование + 2–3 дня отчёт; retest 3–5 дней.

### Deep White (White Box)

- **Для:** перед инвестициями/партнёрством, после инцидента, строгие требования платёжных систем.
- **Входит:** всё из Standard + code review, архитектура, схемы/ledger, секреты/зависимости, криптография,
  отчёт с корневыми причинами + план + **1 retest**.
- **Не входит:** внесение изменений в код клиента, юридические заключения, продакшн-данные.
- **Срок:** 15–25 рабочих дней в зависимости от объёма кода; retest 3–5 дней.

### Retest (отдельно)

- Перепроверка списка находок. Результат — сертификат.
- Срок: 3–5 дней. Условие: клиент указал версии/коммиты исправлений.

### Подписка (continuous)

- Ежемесячный контур: скан + точечные проверки новых релизов + приоритетный retest.
- Для компаний с частыми релизами. Scope и SLA фиксируются отдельно.

## 2. Модель цены (как считать, а не «сколько брать»)

Цена = **база пакета × коэффициенты scope** + retest/подписка.

| Коэффициент | Что увеличивает цену |
|---|---|
| Цели | Количество доменов, приложений, API, репозиториев |
| Режим | White > Grey > Black |
| Домен | Финтех с деньгами/PII дороже игры без денег; оба домена — дороже одного |
| Роли/потоки | Количество ролей, платёжных потоков, валют, интеграций |
| Объём кода (White) | Строки/сервисы/миграции, сложность архитектуры |
| Сроки | Срочность, работа вне окна, weekend |
| Retest/подписка | Отдельные позиции, не «включено всё» |

**Пример расчёта (иллюстрация, не прайс):**
Standard Grey для игры: база × (1 приложение + 1 API + 3 роли + донат) × 1 retest.
Тот же пакет для финтеха с 2 платёжными потоками и KYC: база × (1 приложение + 2 API + 4 роли + платежи/KYC) × 1 retest — дороже.
Точную сумму называй только после intake и scope, а не до них.

**Что не продавай:** «гарантию безопасности», «100% найдём всё», «взлом конкурентов»,
«проверку без разрешения». Это вне услуги и вне закона.

## 3. Воронка продажи

```text
Заявка → Intake-анкета ([templates/intake-questionnaire.md](templates/intake-questionnaire.md))
       → Короткий созвон: цель, активы, сроки, ограничения
       → Предложение: пакет + scope-черновик + цена по модели + сроки
       → Договор + NDA + подписанный scope/RoE
       → Проверка → Отчёт → План → Retest → Сертификат
       → Рекомендация: подписка / повторный аудит / hardening
```

На этапе предложения честно называй ограничения режима: «Black Box не проверяет код» —
это повышает доверие и снижает споры после отчёта.

## 4. Договорные основы (шаблон, не юридическая консультация)

- Предмет: проверка в scope, режим, домен, результат (отчёт, план, retest).
- Разрешение и RoE: клиент разрешает проверку своих систем в scope и окне.
- Конфиденциальность: NDA, хранение и удаление материалов, coordinated disclosure.
- Ответственность: проверка не гарантирует отсутствие уязвимостей; ответственность за
  исправления и эксплуатацию — на клиенте; проверяющий отвечает за качество проверки в scope.
- Приёмка: отчёт передан, вопросы закрыты, план согласован; retest — по дате/версиям клиента.
- Оплата: по этапам (старт / отчёт / retest) или по договору; scope-изменения — допсоглашением.
- Юристом согласуй: обработку персональных данных, регуляторные требования, ограничения
  ответственности, порядок инцидентов.

Шаблон scope/RoE для подписания: [templates/scope-authorization-roe.md](templates/scope-authorization-roe.md).

## 5. Приёмка и гарантии (честные)

- **Гарантия качества проверки:** чек-лист режима+домена пройден, находки с доказательствами,
  независимое ревью. Если чек-лист не пройден — фиксируем «не проверено» и не называем это полным аудитом.
- **Гарантия retest:** перепроверка по списку находок в срок, сертификат с статусами.
- **Не гарантируем:** отсутствие уязвимостей, защиту от всех атак, регуляторное одобрение.
  Это в отчёте и договоре — явно.

## 6. Upsell и повторные продажи

- Retest после исправлений (обязательный следующий шаг).
- Hardening-консультации по P0/P1 (без правок в проде без отдельного договора).
- Подписка для частых релизов.
- Повторный аудит при крупных релизах / раз в 6–12 месяцев (по риску клиента).
- Обучение команды по итогам отчёта (разбор находок, threat model для новых фич).

## 7. Чек-лист продавца перед стартом

- [ ] Intake заполнен, цель и активы понятны.
- [ ] Пакет и режим выбраны по [01-methodology.md](01-methodology.md), ограничения названы клиенту.
- [ ] Цена посчитана по модели scope, а не «на глаз».
- [ ] Договор/NDA/scope/RoE подписаны. Без подписей — не начинаем.
- [ ] Контакты и стоп-условия назначены.
- [ ] Агентский пакет собран по [06-ai-agent-protocol.md](06-ai-agent-protocol.md).
