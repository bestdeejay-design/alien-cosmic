# Навык: Grey Box (`security-audit-grey-box`)

Используй, когда есть тестовые аккаунты, документация и staging, но нет полного кода.
Это стандартный продаваемый пакет для игр и финтеха.

## Чек-лист (детально — [../security-audit-core/support/checklists/grey-box.md](../security-audit-core/support/checklists/grey-box.md))

1. **Всё из Black Box** — с тестовыми доступами.
2. **Роли и AuthZ:** IDOR на чужие объекты, вертикальная/горизонтальная эскалация, tenant isolation, админка/саппорт, MFA.
3. **Логика и состояние:** race conditions, идемпотентность, транзакционность, откаты, отрицательные суммы, подмена цены с клиента.
4. **Сессии/токены:** отзыв, ротация, время жизни, хранение.
5. **Доменный контур:** игра — дюп/фарм/донат/RNG (`security-audit-gaming`); финтех — ledger/вебхуки/KYC/PII (`security-audit-fintech`).
6. **Файлы и интеграции:** загрузки, вебхуки (подпись/replay), ключи и секреты.

## Правила

- Сверяй API-документацию с фактическими эндпоинтами; расхождения — в отчёт.
- Если роль/эндпоинт не выдан — фиксируй «не проверено», а не «всё чисто».
- Threat model обязательна: приоритеты проверок обосновывай ею.
