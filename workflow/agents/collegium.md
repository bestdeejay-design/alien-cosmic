# Протокол коллегии саб-агентов и 2-й волны со сменой ролей (`ADR-0002`)

Этот документ задаёт обязательный для координатора порядок оркестрации саб-агентов до сдачи работы на уровень репо/владельца. Цель — поймать архитектурные дыры, нехватку скиллов и слепые пятна **внутри дешёвой параллельной коллегии сабов**, сократив внешние итерации переделок до минимума.

## 1. Обязательства координатора (Delegation Enforcer)

Координатору запрещено исполнять `size:M` и `size:L` «в одну голову» внутри собственной длинной сессии. На каждую задачу координатор обязан:
1. Поднять профильных саб-агентов по тиру размера (`S` / `M` / `L`).
2. Выдать каждому сабу его ролевую карточку из [`agents/`](./README.md) и **явно включить нужные навыки** из [`skills/`](../skills/README.md) через `scripts/spawn-pack`.
3. Обеспечить, чтобы **Саб-Исполнитель всегда поднимался свежим** (нулевой посторонний контекст: только роль + скиллы + `CONTEXT_PACK`).
4. Не принимать поставку без перекрёстного ревью/коллегии и соблюдения правила ротации ролей ниже.

---

## 2. Поток для `size:M` и `size:L`: Коллегия 4 ролей + 2 волны со сменой ролей

### Шаг 0. Подготовка чистого входа (`Prep`)
1. **Параллельно** запускаются read-only [auditor.md](./auditor.md) (`→ AUDIT_PACK`) и [researcher.md](./researcher.md) (`→ SPEC_PACK`).
2. Read-only [reviewer.md](./reviewer.md) читает оба пакета и пишет **`REVIEWER_KICK`** (3–5 конкретных Pre-Mortem ловушек: за что завернёт сразу и какие edge-case тесты обязательны).
3. Координатор проходит гейт `CONCLUSION` (для `L` — вместе с `ADR`) и собирает единый `CONTEXT_PACK = AUDIT_PACK + SPEC_PACK + REVIEWER_KICK` командой `scripts/spawn-pack`.

### Волна 1. Clean-Room исполнение и параллельная коллегиальная приёмка (4 линзы)
1. Поднимается **полностью свежий** `Саб-Исполнитель-А` ([executor.md](./executor.md) + нужные `skills/` + `CONTEXT_PACK`). Он пишет код строго в радиусе, гоняет `scripts/preflight` и сдаёт дифф `<sha_w1>` + карту хрупкости.
2. **Коллегиальная проверка (параллельно все 4 участника, каждый со своей колокольни задачи):**
   - **Аудитор (Линза 1):** соблюдён ли радиус, целы ли инварианты и вызовы из `AUDIT_PACK`.
   - **Ресёрчер (Линза 2):** соответствует ли код выбранному `SPEC_PACK`, закрыты ли все критерии приёмки без тихих костылей.
   - **Ревьювер-Б (Линза 3):** живой запуск `scripts/preflight`/тестов, проверка всех ловушек `REVIEWER_KICK`, поиск дыр и пограничных входов.
   - **Исполнитель-А (Линза 4):** честная фиксация тонких мест и непроверяемых в песочнице границ.

### Волна 2. Перекрёстная доводка со сменой ролей (`Исполнитель ↔ Ревьювер`)
Чтобы ревьювер не превращался в «диванного критика», а оба участника глубоко включились в реальный код проекта, работает **двухрежимная ротация без нарушения запрета само-ревью**:

1. **Внутри `M/L`-задачи (доводка и стресс-тесты руками вчерашнего ревьювера):**
   - Бывший `Ревьювер-Б` получает карточку [executor.md](./executor.md) (`Исполнитель-Б`) + профильные скиллы и **собственными руками** закрывает замечания коллегии Волны 1 и дописывает жёсткие adversarial/edge-case тесты поверх `<sha_w1>`, создавая коммит `<sha_w2>`.
   - Бывший `Исполнитель-А` получает карточку [reviewer.md](./reviewer.md) (`Ревьювер-А`) и перекрёстно проверяет дифф `<sha_w1>..<sha_w2>`, прогоняя `scripts/preflight` и полный набор тестов.
   - Финальный срез сверяется по всем 4 линзам коллегии: каждый коммит проверен **не его автором** (`sha_w1` проверил Б, `sha_w2` проверил А).
2. **Между парными/соседними задачами проекта (на потоке карточек борда, включая серию `size:S`):**
   - На Задаче №1: `Контур А = Исполнитель`, `Контур Б = Ревьювер`.
   - На соседней Задаче №2 той же зоны: роли **зеркально меняются** (`Контур Б = Исполнитель`, `Контур А = Ревьювер`).

## 3. Быстрый поток для `size:S`: Fast-Track Дуэт (1 волна)

Для малых задач (`size:S`: 1–2 файла, без смены схем/интерфейсов, откат одной правкой):
- Ожидание предварительного `GATE OPEN` до кода **не требуется**: свежий `Исполнитель-А` (с выданным скиллом) за один проход фиксирует мини-аудит/`CONCLUSION`, вносит правку, проходит `scripts/preflight` и отдаёт ветку.
- Свежий независимый `Ревьювер-Б` прогоняет `scripts/preflight` + тесты и даёт `🔎 VERDICT #N — approve <sha7>` (или точный список правок). На следующей `S`-задаче роли А и Б меняются местами.

## 4. Первичный трёхслойный аудит готового проекта (Frontend + API + Backend)

Когда на вход поступает уже существующий проект, которому нужен полный аудит всех слоёв до заведения карточек разработки:
1. Раскатай роли, 11 навыков и генератор в репозиторий проекта (не затирает существующие локальные файлы без `--force`):
   `python3 scripts/install-skills --target /path/to/project --with-harness`
2. Сгенерируй 4 чистых промпта одной командой:
   `python3 scripts/spawn-pack --preset fullstack-audit --output-dir /tmp/audit-packs`
3. Запусти **параллельно** 3 read-only саб-аудитора по слоям (`01-auditor-frontend.md`, `02-auditor-api.md`, `03-auditor-backend.md`), а затем передай их отчёты арбитру межслойных стыков (`04-reviewer-seams.md`) для сборки доказательной матрицы `P0 / P1 / P2` и нарезки карточек `size:S / size:M / size:L`.
