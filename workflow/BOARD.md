# BOARD — учёт задач

## Где живёт учёт

| Инструмент | Назначение |
|---|---|
| **GitHub Projects (борд проекта)** | Видимость задач и колонок; источник статуса — labels в issues |
| **Issues** | Бриф, критерии приёмки, письма-комментарии, вердикты ревью |
| **Mailbox проекта** (в репо проекта) | Письма о поставках, памятки, история — append-only |
| **Статус-карточка** (в репо проекта) | Одностраничное «что сейчас канон», обновляется координатором перед каждым важным событием |
| **HANDOFF** (в репо проекта) | Файл перехода в новую сессию: инфраструктура, открытые пункты, уроки |

## Колонки статусов

| Статус | Значение | Кто двигает |
|---|---|---|
| **Бэклог** | Принято к сведению, очередь не назначена | Координатор |
| **Ждёт** | Назначено, но заблокировано (ждёт аудита/слова владельца/ревью) | Координатор |
| **К работе** | Issue оформлен, исполнитель назначен | Координатор |
| **В работе** | Исполнитель начал | Координатор |
| **На проверке** | Поставка + письмо получены, у ревьювера | Координатор |
| **Правки** | Ревью вернуло список — работает исполнитель | Координатор |
| **На приёмку** | Approve ревьювера, слито, ждёт владельца | Координатор |
| **Готово** | Приёмка владельца | Владелец |

## Правила

1. Задача без issue не существует (нет брифа — нет работы).
2. Карточка на борд добавляется координатором в момент оформления issue.
3. Статус задачи задаёт label `status:*` в issue; карточка борда — вид поверх него. При расхождении координатор устраняет дрейф согласно последнему обоснованному переходу (KNOWLEDGE_BASE §4).
4. Закрытые issue без приёмки владельца (откаты, отзыв) — закрываются с комментом-обоснованием.
5. Приоритеты владелец задаёт словом; координатор отражает их порядком карточек и метками.

## Статусы соседних сессий (владелец, 03.11.2026)

Каждая сессия обязана видеть на борде, что делают соседние: поля карточки
«Сессия (кто ведёт)» и «Этап поставки» заполняются при любом переходе.
Взял задачу — «В работе» + своя сессия; сдал — «На проверке»/«На приёмку».
Коммуникация между сессиями — комментарии к issue борда, не личные каналы.
Сессия без карточки не существует: её коммиты не ревьюятся и не деплоятся.

## Движение задач — только координатор (владелец, 03.11.2026)

Уточнение к таблице статусов и к любым формулировкам о самостоятельном движении:

- координатор создаёт задачу и передаёт её исполнителю/сабу;
- исполнитель (и его сабы) **только делает работу**: сдаёт её (ветка + письмо о поставке /
  маркер `📬 DELIVERED`) и отчитывается координатору;
- **все отметки прохождения** — READ-подтверждения, GATE OPEN/CLOSED, переводы статусов
  («В работе», «На проверке», «Правки», «На приёмку»…) — ставит **только координатор**,
  проверяя каждый шаг;
- исполнитель не двигает борд, не переводит статусы и не закрывает задачи — даже свои;
  просьба исполнителя о смене статуса — маркером (`📬 DELIVERED`, `⛔ BLOCKED`) координатору;
- исключение (решение владельца, делегированное координатору 03.11): автоматический
  claim исполнителя через `wait-signal --claim` разрешён — при выигрыше арбитража
  скрипт сам переводит `status:ready` → `status:in-progress` и ставит `to:*`;
  все остальные переходы — только координатор.
