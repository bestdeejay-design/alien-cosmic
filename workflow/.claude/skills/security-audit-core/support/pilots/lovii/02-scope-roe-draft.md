## 3. Scope

- **Режим:** Grey Box (фаза 1 — Black Box по staging, фаза 2 — Grey Box с доступами).
- **Домен:** финтех + маркетплейс + лояльность (баллы).
- **Основные цели (активные проверки):**
  - `staging.example.com` — каталог, магазины, авторизация, профиль, PAY, баллы, заказ/оплата (моки).
  - `b2b-staging.example.com` — кабинет МСП, вход OTP/passkey, данные точки, загрузка фото.
  - `api-staging.example.com` — API за моками (по документации от клиента — TBD).
- **Пассивно только (без атак):**
  - `app.example.com`, `b2b.example.com`, `example.com` — публичное чтение, сравнение поведения staging/prod.
  - `b2b.example.com/storage/...` — хранилище: проверка прав только по согласованным тестовым объектам.
- **Вне scope:**
  - Инфраструктура и системы <bank>, платёжные сети, СБП, операторы связи (СМС).
  - `demo.example.com` — TBD: исключить или согласовать отдельно.
  - DDoS/нагрузочные атаки, social engineering, физический доступ, атаки на третьих лиц.
  - Реальные боевые платежи и любые операции с боевыми деньгами.
- **Тестовые доступы:** покупатель ×2, точка МСП, админ/оператор (если есть) — TBD: выдать до фазы 2.

## 5. Запреты

По [03-process-and-rules.md](../../03-process-and-rules.md) §3: без отдельного разрешения — никаких атак
вне scope, DDoS, удаления/порчи данных, эксфильтрации сверх PoC, social engineering,
использования секретов вне scope, публикации до coordinated disclosure.
Отдельно: **не трогать данные реальных людей**, если они окажутся на staging.

## 6. Стоп-условия

- На staging обнаружены реальные ПДн или ключи прода → стоп, уведомление.
- Доступ к боевым деньгам или боевому ledger → стоп.
- Деградация сервиса/влияние на прод → стоп.
- Отзыв разрешения клиентом → немедленный стоп.

## 8. Результат и приёмка

- Результат: executive summary + технический отчёт + план исправлений + retest.
- Сроки: Standard Grey — 10–15 дней проверки + 2–3 дня отчёт ([08-service-packages.md](../../08-service-packages.md)).
- Приёмка: отчёт передан, вопросы закрыты, план согласован, дата retest зафиксирована.

## 9. Ограничение по среде

Находки на staging помечаются «подтверждено на staging». Перенос на прод не утверждается без проверки.
Отчёт не гарантирует отсутствие уязвимостей и не заменяет юридическую/регуляторную оценку.
