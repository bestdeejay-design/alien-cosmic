# Словарь простыми словами

> Читай как шпаргалку. Термин — «что это на пальцах» — «зачем тебе это знать».
> Если клиент или агент употребляет термин иначе — уточни по этому словарю и зафиксируй в scope.

## Базовые понятия

| Термин | Простыми словами | Зачем знать |
|---|---|---|
| **Аудит безопасности** | Системная проверка: код, архитектура, процессы, конфиги. Шире, чем пинтест. | Продаёшь «аудит», когда проверяешь не только снаружи, но и внутри |
| **Пентест (penetration test)** | Попытка «пробить» защиту в рамках разрешения: найти путь от входа до ущерба. | Клиент часто просит именно «пинтест» — уточни режим и scope |
| **Уязвимость (vulnerability)** | Слабое место, которым можно воспользоваться. Не баг вообще, а именно слабое место. | Каждая находка отчёта — это уязвимость с риском |
| **Эксплойт** | Способ воспользоваться уязвимостью. В отчёте — описание сценария, а не «оружие». | Не публикуй готовые эксплойты шире, чем нужно для доказательства |
| **PoC (Proof of Concept)** | Доказательство: шаги, при которых уязвимость воспроизводится. | Без PoC находка — мнение, а не факт |
| **Scope** | Границы проверки: что проверяем, что не трогаем, в какие сроки. | Главный документ: всё вне scope — запрещено |
| **RoE (Rules of Engagement)** | Правила взаимодействия: окно, запреты, кому звонить при проблемах, стоп-условия. | Защищает и тебя, и клиента при инцидентах |
| **Threat model** | Модель угроз: кто атакует, что защищает, какие сценарии реалистичны. | Помогает не проверять «всё подряд», а бить по реальным рискам |
| **Attack surface** | Поверхность атаки: всё, что доступно снаружи (сайты, API, приложения, почта, CDN). | Чем больше поверхность — тем дороже и дольше проверка |
| **CVSS** | Стандартная шкала оценки серьёзности (0–10). См. [07-deliverables.md](07-deliverables.md). | Единый язык для приоритизации исправлений |

## Режимы проверки

| Термин | Простыми словами |
|---|---|
| **Black Box** | Знаешь только то, что видит любой из интернета. Кодов нет. |
| **Grey Box** | Знаешь часть: тестовые доступы, документацию, архитектуру. Полного кода нет. |
| **White Box** | Знаешь всё: код, схемы, конфиги, логи. Проверяешь как инсайдер. |

Подробно — [01-methodology.md](01-methodology.md).

## Типы проверок (не путай)

| Термин | Простыми словами |
|---|---|
| **Vulnerability scan** | Автоматический скан сканером. Быстро, но поверхностно и с ложными срабатываниями. Не пинтест. |
| **Code review (ревью кода)** | Чтение кода с точки зрения безопасности. Часть White Box. |
| **Configuration review** | Проверка настроек: серверы, CDN, заголовки, права, секреты. |
| **Social engineering test** | Проверка людей: фишинг, звонки. Отдельный тип, только с особым разрешением. По умолчанию не входит. |
| **Red team / Blue team** | Red — атакует, Blue — защищает и ловит. Red team — шире пинтеста (цель — проверить детект, а не только дыры). |
| **Retest** | Перепроверка после исправлений. Без него «исправлено» — на веру. |

Подробно — [02-types-of-checks.md](02-types-of-checks.md).

## Технические термины, которые встретишь в отчётах

| Термин | Простыми словами |
|---|---|
| **IDOR** | Подмена ID: поменял `user/123` на `user/456` — и получил чужие данные. Проверка прав на объект, а не только «вошёл в систему». |
| **AuthN / AuthZ** | Authentication — кто ты (вход). Authorization — что тебе можно (права). Путать нельзя: вход есть, а прав на чужое быть не должно. |
| **Injection (SQLi, XSS и др.)** | Внедрение чужого кода через ввод: в базу, в страницу, в команду. |
| **SSRF** | Сервер по твоей просьбе ходит по внутренним адресам. |
| **CSRF** | Подделка запроса от имени жертвы в браузере. |
| **Race condition** | Гонка: два запроса одновременно — и баланс/валюта/инвентарь дублируется. Критично для денег и игровой экономики. |
| **Idempotency** | Повтор запроса не создаёт дубль. Без неё повторный вебхук = двойное списание. |
| **Ledger** | Журнал учёта денег/валюты: кто, кому, сколько, когда. В финтехе — сердце системы. |
| **PII / персональные данные** | Данные, по которым можно найти человека: ФИО, паспорт, телефон, e-mail, платёжные данные. |
| **Secrets** | Пароли, API-ключи, токены, приватные ключи. Утечка = компрометация. |
| **MFA / 2FA** | Второй фактор входа. Для админов и денег — обязателен. |
| **Rate limiting** | Ограничение частоты запросов. Без него — перебор и флуд. |
| **DDoS** | Распределённый флуд запросами. Пинтест DDoS — только в очень узких рамках и почти никогда в стандартном пакете. |

## Игровые термины

| Термин | Простыми словами |
|---|---|
| **Client-authoritative** | Клиент решает, что произошло (урон, награда). Легко читить: правишь клиент — правишь результат. |
| **Server-authoritative** | Решает сервер. Клиенту нельзя верить. Правильный подход для экономики. |
| **Duping** | Дублирование предметов/валюты через баг (гонка, повтор, откат). |
| **Anti-cheat** | Система поиска читов. Проверяется на обходы, но не «гарантирует» отсутствие читов. |
| **RNG** | Генератор случайности (лут, дроп, рулетки). Проверяется на предсказуемость и честность. |
| **Economy exploit** | Способ сломать игровую экономику: фарм, дюп, сговор, накрутка. |

## Финтех-термины

| Термин | Простыми словами |
|---|---|
| **KYC / AML** | Знай клиента / противодействие отмыванию. Проверка личности и подозрительных операций. |
| **Double spend** | Двойная трата одних средств. |
| **Settlement** | Расчёты/клиринг: как деньги доходят от отправителя к получателю. |
| **Chargeback** | Возврат платежа по спору. Злоупотребление — отдельный риск. |
| **PCI DSS** | Стандарт безопасности карточных данных. Работа с картами — только по нему и с юристом/аудитором. |

## Как отвечать, если не знаешь термин

Не выдумывай. Скажи: «Уточню по словарю/методике и зафиксирую в scope», проверь
[01-methodology.md](01-methodology.md) / [02-types-of-checks.md](02-types-of-checks.md) и только потом отвечай.
Непроверенное, поданное как факт, — нарушение правила достоверности (см. `PROTOCOL.md` §8, если он есть в репозитории).
