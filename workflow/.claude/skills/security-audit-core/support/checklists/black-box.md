# Чек-лист: Black Box

> Режим: только публичное. Агент отмечает каждый пункт: `проверено / не проверено (причина) / не применимо`.
> Находка — только с доказательствами по [templates/finding.md](../templates/finding.md).

## Recon и карта поверхности

- [ ] Список целей из scope сверен с фактическими (домены, поддомены, приложения, API).
- [ ] DNS/TLS: сертификаты, протоколы, слабые шифры, HSTS.
- [ ] Открытые порты/сервисы (без агрессивного сканирования вне scope).
- [ ] Технологии по заголовкам/баннерам/ошибкам; раскрытие версий.
- [ ] Публичные репозитории/утечки (только публичное чтение): секреты, ключи, схемы.
- [ ] Карта эндпоинтов: формы, загрузки, публичные API, параметры.

## Аутентификация и доступ снаружи

- [ ] Регистрация/вход/восстановление: enumeration, перебор, слабые пароли, капча/лимиты где уместно.
- [ ] MFA: где должна быть, где отсутствует.
- [ ] Сессии: время жизни, хранение, отзыв (в объёме публичного доступа).
- [ ] IDOR/доступ к чужим объектам без аккаунта и с минимальным публичным аккаунтом.

## Ввод, инъекции, файлы

- [ ] XSS (отражённый/хранимый в публичных полях), SQLi, SSRF, path traversal — безопасными PoC.
- [ ] File upload: типы, расширения, хранение, доступ по прямым ссылкам.
- [ ] Параметры: типы, длины, диапазоны; серверная валидация, а не только клиентская.

## Конфигурация

- [ ] Security headers (CSP, X-Frame-Options, Referrer-Policy и др.), CORS allowlist.
- [ ] Раскрытие ошибок/стектрейсов, debug-режимы, directory listing.
- [ ] Rate limiting на вход/восстановление/поиск; защита от перебора.

## Бизнес-логика снаружи

- [ ] Обход оплаты/доната: подмена цены/количества/товара, повторное использование купонов.
- [ ] Повторные запросы, двойной клик, replay публичных операций.
- [ ] Публичные лимиты: накрутка метрик, спам, флуд (без DoS).

## Финал Black Box

- [ ] Список «не проверено» составлен (код, внутренние сервисы, роли без доступа и т.д.).
- [ ] Ограничения режима явно в отчёте: «внутри не проверяли».
