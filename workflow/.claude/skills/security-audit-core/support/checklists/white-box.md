# Чек-лист: White Box

> Режим: Grey Box + полный доступ (код, схемы, конфиги, логи). Аудит read-only:
> агент не вносит изменения в код клиента.

## Всё из Grey Box

- [ ] См. [grey-box.md](grey-box.md) — выполняется полностью.

## Код: клиент, сервер, API, воркеры

- [ ] Server-authoritative vs client-authoritative: где клиент решает то, что должен решать сервер.
- [ ] AuthN/AuthZ: проверка прав на объект на каждом чтении/изменении, а не только «вошёл».
- [ ] Валидация входа: схемы, типы, диапазоны, лимиты; пагинация без безлимитных выборок.
- [ ] Инъекции: SQL/NoSQL, XSS, SSRF, path traversal, command injection — паттерны и PoC.
- [ ] Криптография: хранение паролей (Argon2id/bcrypt), JWT, подписи, TLS, хранение токенов.
- [ ] Секреты в коде/конфигах/репозиториях/клиентском бандле; секреты в логах.
- [ ] Ошибки: пустые catch, стектрейсы наружу, честные HTTP-коды, таймауты внешних вызовов.

## Данные, ledger, транзакции

- [ ] Схемы БД: индексы, уникальность, внешние ключи, инварианты денег/валюты.
- [ ] Транзакции: атомарность, частичные записи, N+1, гонки при параллельных запросах.
- [ ] Ledger (финтех) / экономика (игра): двойная запись, идемпотентность, сверка.
- [ ] Миграции: версионирование, обратная совместимость, откат без дублей.

## Конфиги, IaC, CI/CD, зависимости

- [ ] Конфиги: обязательные переменные, значения по умолчанию, разделение test/prod.
- [ ] IaC: права, публичные ресурсы, шифрование, бэкапы.
- [ ] CI/CD: секреты, provenance, права на репо, кто может деплоить.
- [ ] Зависимости: уязвимые версии, lock-файлы, supply chain.

## Логи, мониторинг, аудит

- [ ] Что логируется / что не должно (секреты, PII, токены); маскирование.
- [ ] Audit trail: append-only, синхронизация времени, защита от правок.
- [ ] Алерты: аномальные операции, массовые выводы, сбои сверки, попытки перебора.

## Тесты безопасности

- [ ] Есть ли тесты на права, идемпотентность, инварианты денег/валюты, race.
- [ ] Покрытие критичных потоков; тесты на реальных сценариях, а не только на моках.

## Финал White Box

- [ ] Корневые причины указаны (код/архитектура), а не только симптомы.
- [ ] Рекомендации системные: что чинить в паттерне, а не только в одном месте.
- [ ] «Не проверено» и ограничения (продакшн-данные, 0-day, внешняя эксплуатируемость) в отчёте.
