# Игровые проекты: риски и проверки

> Домен: игры и около-игровые (платформы, маркетплейсы предметов, донат, турниры, UGC).
> Деньги здесь — донат, игровая валюта, предметы, аккаунты. Главный риск — **экономика и читы**,
> а не только «взлом сайта».

## 1. Модель угроз (что атакует злоумышленник)

- **Чит-игрок:** хочет выигрывать/фармить без усилий, продавать аккаунты/валюту.
- **Фармер/ботовод:** автоматизация, мультиаккаунты, сговор.
- **Мошенник:** кража аккаунтов, фишинг, подделка оплаты.
- **Вандал:** порча данных, DDoS, гриферство через баги.

## 2. Критичные зоны проверки

### 2.1. Клиент vs сервер (самая частая дыра)

- [ ] **Server-authoritative:** урон, награды, дроп, баланс, инвентарь решает сервер, а не клиент.
- [ ] Клиент не может подделать: HP, координаты, таймеры, результаты матчей, RNG.
- [ ] Сервер валидирует: скорость, дальность, кулдауны, последовательность действий.
- [ ] Модификация клиента (память, пакеты, прокси) не даёт преимущества без детекта.
- [ ] Replay/подделка пакетов: подпись, nonce, защита от повторов.

### 2.2. Экономика и дюп

- [ ] Дюп через race: параллельные покупки/продажи/передачи одного предмета.
- [ ] Дюп через откат/повтор: повторный запрос, обрыв сети, двойной клик, повторный вебхук оплаты.
- [ ] Отрицательные/нулевые/переполненные суммы, количества, цены.
- [ ] Подмена цены/количества/валюты на клиенте (цена не берётся из клиента).
- [ ] Транзакционность: покупка = списание + выдача атомарно; частичная запись запрещена.
- [ ] Идемпотентность: повтор оплаты/покупки не создаёт дубль.
- [ ] Торговля/обмен: нельзя продать то, чего нет; нельзя передать дважды; нельзя обойти комиссию/налоги.
- [ ] Фарм: лимиты, кап, анти-бот, мультиаккаунт, сговор в турнирах/рейтингах.

### 2.3. Донат и платежи

- [ ] Подделка receipt (Apple/Google/Steam/платёжные системы): подпись проверяется на сервере.
- [ ] Повторное использование receipt, чужой receipt, подмена суммы/товара.
- [ ] Вебхуки: подпись, идемпотентность, порядок, защита от повторов и подделок.
- [ ] Возвраты/chargeback: валюта/предметы отзываются корректно, без дюпа.
- [ ] Промокоды/купон: одноразовость, лимиты, нельзя комбинировать запрещённое.

### 2.4. RNG, лутбоксы и честность

- [ ] RNG на сервере, с достаточной энтропией; сид не предсказуем и не уходит клиенту.
- [ ] Лутбокс/рулетка: шансы соответствуют заявленным, выдача — сервером, аудит выдачи.
- [ ] Нельзя «переролить» повторным запросом/перезапуском.
- [ ] Логи выдачи сохраняются для разбора споров.

### 2.5. Аккаунты и доступ

- [ ] Регистрация/вход/восстановление: enumeration, перебор, слабые пароли, отсутствие MFA для ценных аккаунтов.
- [ ] Сессии/токены: отзыв, время жизни, хранение, привязка к устройству где уместно.
- [ ] IDOR: чужой инвентарь, профиль, история покупок, чаты.
- [ ] Модерация/админка: права, аудит действий, защита от злоупотреблений.
- [ ] UGC/моды/чат: XSS, загрузка вредоносного, модерация, защита от спама/флуда.

### 2.6. Античит и целостность

- [ ] Что именно детектит античит, что — серверная валидация, что — ручная модерация. Не смешивай.
- [ ] Обходы: модификация клиента, автоматизация, эмуляторы, прокси — в рамках scope и без деструкции.
- [ ] Ложные срабатывания: честные игроки не должны страдать; апелляция и аудит банов.
- [ ] Клиентский античит не является единственной линией защиты для экономики.

### 2.7. Инфраструктура и данные

- [ ] API: AuthZ, rate limiting, пагинация, защита от перебора и накрутки метрик.
- [ ] Сохранения/профиль: целостность, версионирование, защита от подделки и отката.
- [ ] Бэкапы и восстановление: откат не должен дублировать валюту/предметы.
- [ ] Логи: что пишется, что не должно (секреты, токены), защита от подделки логов.

## 3. Приоритизация для игр

| Приоритет | Пример | Почему |
|---|---|---|
| P0 | Дюп валюты, подделка оплаты, client-authoritative награды | Прямая потеря денег/экономики |
| P1 | IDOR на инвентарь/профиль, кража аккаунтов, RNG-предсказуемость | Потеря аккаунтов/предметов, репутация |
| P2 | Накрутка метрик, спам, слабые лимиты | Искажение данных, нагрузка |
| P3 | Информационные утечки, misconfig | Усиливает другие атаки |

## 4. Что агент обязан зафиксировать для игры

- Тип клиента (мобильная/PC/браузерная, мультиплеер/сингл, F2P/P2P), где живёт логика (клиент/сервер).
- Где живёт экономика: валюты, предметы, донат, торговля, турниры.
- Какие читы реалистичны для жанра и масштаба (не «все читы мира»).
- Что проверено на staging с тестовыми аккаунтами, что — только снаружи.
