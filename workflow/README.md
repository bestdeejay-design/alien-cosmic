# AGENTS — рабочее пространство команды ИИ-агентов

Канон процессов, правил и статусов для совместной работы владельца и ИИ-агентов
нескольких параллельных сессий и агентов над любым проектом группы.

> Здесь только процессы, правила и статусы. Независимо от настроек доступа секреты
> (токены, креды, адреса инфраструктуры) сюда не кладём никогда.

## Команда

| Роль | Кто | Суть |
|---|---|---|
| **Владелец** | назначается проектом (владелец продукта/репозитория) | Приоритеты, продуктовые решения, финальная приёмка. Единственный, кто меняет протокол |
| **Координатор** | назначается владельцем на проект | Единственная точка входа для задач. Issues с брифом и критериями, назначение исполнителей, борд, слияния, версия продукта |
| **Исполнитель** | назначается координатором | Работает только в своей ветке поставки, только по назначенным задачам, поставка = письмо |
| **Ревьювер** | назначается координатором, не автор работы | Обязательное второе заход-ревью любой работы агентом, который не её автор |

## Ключевые принципы (коротко)

1. **Задача — только через координатора.** Слово владельца напрямую исполнителю брифом становится после оформления координатором.
2. **Поставка — никогда в main.** Ветка + письмо с диапазоном коммитов.
3. **Коллегия сабов и ревью не-автором.** Координатор обязан выдавать саб-агентам роли (`agents/`) и навыки (`skills/`); исполнитель всегда свежий; до сдачи координатору проходит коллегиальная проверка и 2-я волна со сменой ролей (`ADR-0002`).
4. **Приёмка по делегированию (`ADR-0001`).** Операционная приёмка цикла и слияния (по гейтам и ревью не-автором) — координатор; продуктовые решения, продуктовая приёмка и право вето по любому решению — владелец.
5. **Предполётная проверка и регресс перед каждым пушем** (`python3 scripts/preflight` + канонический список проекта) — без сокращений; прямые пуши в `main` блокируются локальным хуком `.githooks/pre-push` (серверная автоматика GitHub Actions в хабе не используется — решение владельца 14.11, см. [OPS.md](./OPS.md)).
6. **Большие задачи — по конвейеру:** аудит → ресерч → репозиторий этапа → задачи на борд → перекрёстный аудит агентов → реализация. Скачки через ступени не признаются.

## Правило слоёв (владелец, 03.11.2026; усилено `ADR-0003` от 11.11.2026)

Этот репозиторий — **стерильное переносимое ядро** для любых проектов и агентов: только
практики и инструменты совместной работы нескольких сессий. Никаких зашитых имён сабов,
платформ, продуктов, личных аккаунтов и проектного жаргона в живом каноне нет.

Каждый координатор копирует канон в свой проектный репозиторий и адаптирует его под себя
в проектном оверлее (`PROJECT.md` и `project.json`): свой ростер исполнителей (`to:<id>`),
префиксы веток, команды регресса, замороженные зоны и отображение окружений.
Архив истории становления самого канона изолирован в [`docs/history/`](./docs/history/README.md)
и в проектные репозитории не копируется.

## Custodians — фоновые агенты гигиены (пилот, #127)

Read-only наблюдатели непрерывной гигиены — обёртки над существующими скриптами
(`scripts/custodian`, роли объявляются в `project.json`, ядро не расширяется).
Только печатают маркеры `👤 NEEDS-HUMAN`, не пишут код и не трогают `status:*`/`to:*`;
лимит шума — 3 ложных срабатывания = пауза роли. Подробности и схема —
[docs/KNOWLEDGE_BASE.md §7](./docs/KNOWLEDGE_BASE.md).
