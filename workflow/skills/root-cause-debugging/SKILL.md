# Навык: Поиск первопричины бага (`root-cause-debugging`)

Используй этот навык на любой задаче `type:bugfix`, падении CI, гонке или регрессии.

## Железный закон

**Запрещено писать фикс до того, как воспроизведён отказ и названа точная строка первопричины.** Обёртка `if x is None: return` в месте падения без понимания, откуда пришёл `None`, — это маскировка бага и гарантированный возврат на ревью.

## Четырёхшаговый протокол расследования

1. **Зафиксируй воспроизведение:**
   - напиши минимальный падающий тест или одну команду терминала, которая стабильно воспроизводит дефект;
   - проведи A/B-проверку на базовом коммите (`git worktree` / `git stash`), чтобы точно знать: баг уже жил в `main` или внесён текущей веткой.
2. **Трассируй назад от симптома к источнику (FE ← API ← BE ← БД):**
   - не чини там, где взорвалось; иди вверх по цепочке вызовов до первого места, где валидный инвариант превратился в битое состояние;
   - проверь расхождение форматов на границах (регистр полей, таймзона, `null` против пустого списка, код выхода `0` при ошибке, пропуск `skipped`/`304`).
3. **Проверь единственную гипотезу за раз:**
   - сформулируй проверяемое предсказание («если причина в X, то при входе Y лог/тест покажет Z»); не накладывай три правки поверх друг друга вслепую.
4. **Почини источник и запри регрессионным тестом:**
   - тест обязан **падать** без твоего фикса и **проходить** с ним;
   - проверь соседние вызовы того же паттерна в пределах радиуса задачи (если вне радиуса — вынеси в блок кандидатов `DEBT.md`).
