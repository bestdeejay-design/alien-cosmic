# Навык: Black Box (`security-audit-black-box`)

Используй, когда проверяющий знает только публичное: домены, приложения, открытые API. Кодов нет.

## Чек-лист (детально — [../security-audit-core/support/checklists/black-box.md](../security-audit-core/support/checklists/black-box.md))

1. **Recon:** DNS/TLS, порты/сервисы, технологии, публичные репозитории/утечки, карта эндпоинтов.
2. **Аутентификация снаружи:** enumeration, перебор, слабые пароли, MFA, сессии, IDOR через публичные API.
3. **Ввод:** XSS, SQLi, SSRF, path traversal, file upload — безопасными PoC, без деструкции.
4. **Конфигурация:** headers, CORS, TLS, раскрытие ошибок, debug-режимы, rate limiting.
5. **Бизнес-логика снаружи:** обход оплаты/доната, подмена цены/количества, повтор купонов, replay.

## Правила честности

- В отчёте явно: «внутри не проверяли». Black Box не доказывает отсутствие внутренних дыр.
- Ложные срабатывания сканера разбирать вручную; вывод по поведению без кода помечать как гипотезу,
  если нет PoC.
- Список «не проверено» обязателен: код, внутренние сервисы, роли без доступа.
