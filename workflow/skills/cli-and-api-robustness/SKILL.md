# Навык: Надёжность API, бэкенда и CLI (`cli-and-api-robustness`)

Используй этот навык при разработке, аудите и ревью серверных обработчиков, интеграций, воркеров и консольных скриптов.

## Чек-лист серверного кода и HTTP API

1. **Жёсткая граница входа и объектные права:**
   - валидируй схему, типы, диапазоны и лимиты тела/параметров до вызова бизнес-логики;
   - проверяй право текущего субъекта именно на запрашиваемый объект (защита от `IDOR`), а не только факт входа в систему.
2. **Атомарность, идемпотентность и транзакции:**
   - изменения связанных таблиц выполняй в одной транзакции; не держи открытую транзакцию БД во время медленного внешнего сетевого вызова;
   - повтор запроса при сбое сети не должен создавать дубликаты или переводить сущность в невалидное состояние.
3. **Таймауты, пагинация и квоты внешних API:**
   - у любого сетевого/процессного вызова обязан быть явный `timeout`;
   - на поллинге и списках учитывай пагинацию (`per_page`, следующая страница), условные запросы (`If-None-Match` / `HTTP 304` с пустым телом) и обработку `429`/`5xx` с джиттером.
4. **Структурированные ошибки и чистота секретов:**
   - клиенту возвращай предсказуемый формат ошибки и точный HTTP-код без внутренних стектрейсов, SQL-текстов и токенов; секреты читай только из окружения.

## Чек-лист CLI-скриптов (`bash` / `python`)

- В bash: `set -euo pipefail`, проверка зависимостей на старте, кавычки вокруг переменных, `bash -n` без предупреждений.
- Разделяй потоки: машиночитаемый результат — в `stdout`, диагностика и ошибки — в `stderr`; коды возврата детерминированы и документированы (`0` — успех, ненулевые — конкретные классы ошибок).
