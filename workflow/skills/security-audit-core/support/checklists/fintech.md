# Чек-лист: Финтех и около-финтех

> Дополнение к чек-листу режима. Каждый пункт: `проверено / не проверено (причина) / не применимо`.
> Только тестовые данные и staging без отдельного разрешения. Детали — [05-fintech.md](../05-fintech.md).

## Ledger и деньги

- [ ] Двойная запись, сходимость баланса, нельзя создать деньги из воздуха.
- [ ] Double spend / race на списание/перевод/вывод; отрицательные балансы.
- [ ] Идемпотентность платежей/переводов/выводов; ключ идемпотентности.
- [ ] Транзакционность и откат; нет «списано, но не зачислено».
- [ ] Округления, валюты, комиссии, конвертация.
- [ ] Лимиты: операция/день/получатель/вывод; обход через разбиение/мультиаккаунты.
- [ ] Возвраты/отмены/chargeback без дюпа; сверка ledger ↔ провайдер.

## Платежи и вебхуки

- [ ] Подпись вебхуков, replay-защита, идемпотентность, порядок/статусы.
- [ ] Сумма/валюта/получатель не берутся с клиента; receipt проверяется на сервере.
- [ ] Таймауты/повторы без дублей; честные статусы и коды.
- [ ] Тестовые/боевые ключи разделены.

## Доступ и права

- [ ] IDOR на счета/карты/выписки/документы; tenant isolation.
- [ ] Роли: клиент/мерчант/оператор/админ/саппорт; саппорт без авто-доступа к средствам.
- [ ] MFA для админов/операторов и чувствительных операций.
- [ ] Сессии/токены: отзыв, ротация, хранение.

## KYC/AML и PII

- [ ] KYC нельзя обойти; статусы проверяются на сервере на каждой операции.
- [ ] AML-пороги и мониторинг — по процессу клиента.
- [ ] PII: минимизация, шифрование, доступ по необходимости, сроки, удаление.
- [ ] PII/секреты не в логах; маскирование в UI/логах; экспорт с аудитом.

## API, ключи, секреты, операции

- [ ] API-ключи: энтропия, хеш-хранение, scopes, лимиты, отзыв/ротация, last-used.
- [ ] Секреты провайдеров: secret manager, ротация, аудит чтения; не в клиент/логи/URL.
- [ ] Rate limiting, перебор, enumeration, credential stuffing.
- [ ] Audit trail append-only; мониторинг аномалий; бэкапы без дублей при восстановлении.
- [ ] Криптография: Argon2id/bcrypt, подписи, TLS; зависимости и CI/CD.
