# Threat model <client>

> Активы → злоумышленники → сценарии → приоритеты. Основа для SPEC_PACK.

## Активы

- Деньги: платежи покупателей, выплаты точкам/сети, пул платформы, PAY-балансы.
- Баллы: эквивалент денег (1:1), начисление/трата/вывод через СБП.
- Данные: телефоны, профили, данные точек, фото, заказы, чеки.
- Доверие: тарифы, сплит <split>, чеки 54-ФЗ, репутация у банка и точек.

## Злоумышленники

- **Покупатель-мошенник:** хочет бесплатные товары, дюп баллов, чужой баланс.
- **Точка-мошенник:** хочет обойти комиссию/тариф, накрутить продажи, украсть чужие данные.
- **Фармер:** мультиаккаунты, боты, сговор представитель/точка.
- **Внешний атакующий:** кража аккаунтов, перебор OTP, IDOR, утечка секретов.
- **Инсайдер:** злоупотребление админ/саппорт-правами (если есть).

## Сценарии (приоритет)

| # | Сценарий | Приоритет |
|---|---|---|
| T1 | Дюп баллов: race/повтор/откат при начислении/трате/выводе | P0 |
| T2 | Обход оплаты: подмена цены/суммы, подделка receipt/вебхука, повторное использование | P0 |
| T3 | IDOR: чужой профиль/заказ/баланс/PAY, чужая точка в b2b, фото по прямым ссылкам | P0/P1 |
| T4 | OTP/passkey: перебор кода, enumeration, сессия не отзывается | P1 |
| T5 | <tariff-1> <rate-1>: обход лимита <limit-1> через мультиаккаунты, подмена выручки | P1 |
| T6 | QR-онбординг: подделка/повтор, захват чужого кабинета точки | P1 |
| T7 | PII/секреты в логах, клиентском бандле, URL; массовая выгрузка | P1 |
| T8 | Накрутка: фейковые заказы/точки, сговор сети, накрутка пула | P2 |
| T9 | Misconfig: headers, CORS, TLS, раскрытие ошибок, debug | P2 |

## Риски, специфичные для staging

| # | Сценарий | Приоритет |
|---|---|---|
| S1 | Staging содержит реальные ПДн или ключи прода | P1 (проверить до активных тестов) |
| S2 | Staging открыт в поисковики и используется как «витрина» | P2 |
| S3 | Staging-моки отключены на отдельных флоу → тест реально идёт в банк | P0 (стоп-условие) |
| S4 | Общие БД/шины: тестовые заказы попадают в прод | P1 |
| S5 | Staging-аккаунты с правами прода (админ) | P1 |

## Границы доверия

- Клиент (app/b2b) **никогда** не решает: цену, баланс баллов, статус платежа, тариф, сплит.
- Решает сервер + банк (<bank>). Всё, что приходит с клиента, — недоверенное.
- Хранилище фото и API — за проверкой прав на каждый объект, а не «ссылка есть — доступ есть».

## Что проверяем глубже

T1–T4 — в первую очередь (деньги и доступ). T5–T7 — в том же пилоте.
T8–T9 — по остаточному времени, фиксируем «не проверено», если не успеваем.
