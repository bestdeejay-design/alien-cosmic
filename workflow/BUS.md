# BUS — шина координации агентов на GitHub (v0, из живых прогонов 27.10)

Одна шина для всех узлов: координатор, локальные сессии (со своими субагентами),
внешние агенты. Ни один узел не пишет другому напрямую — только через общий репозиторий.
Владелец не передаёт сообщения: он видит всё на борде.

## Узлы и адресация

| Узел | Как получает работу | Как сдаёт |
|---|---|---|
| Координатор (1) | слово владельца / маркеры шины | гейты, приёмка, задачи, решения |
| Локальная сессия (N, паркованная) | скан issues `label:<роль> + status:ready` каждые 60–120с | маркеры + ветка |
| Внешний агент (N) | launch/CONTINUE-пакет от владельца | пуш своей ветки + маркеры |
| Субагенты | поднимает узел сам | через своего родителя |

## Сообщения шины (маркеры — первая строка комментария)

| Маркер | Кто | Значение |
|---|---|---|
| `🚀 LAUNCH` / `🔄 CONTINUE` / `🔥 HOTFIX` | координатор | задача узлу (самодостаточный пакет: КТО ТЫ / ГДЕ ЧТО ЛЕЖИТ / порядок) |
| `👀 READ — принял #N` | исполнитель | подтверждение прочтения; claim отдельный |
| `🎯 CONCLUSION` | исполнитель | решение до кода (гейт для M/L, для S — компактно) |
| `✅ GATE OPEN` / `❌ GATE CLOSED — причина` | координатор | разрешение на ACTION / возврат |
| `🏁 DONE #N — <ветка>, <артефакт>` | пишущие в issues | поставка |
| `📬 DELIVERED #N` (письмо-файл MAIL.md в ветке) | внешние без записи в issues | поставка (ретрансляция координатором) |
| `👤 NEEDS-HUMAN #N — <что решать>` | любой | требуется решение владельца |
| `🔍 QA — OK/FAIL: <что проверил>` | QA-узел | вердикт проверки |
| `✋ CLAIM #N — <кто>` | узел роя | захват уже увиденной задачи (optimistic; аренда + heartbeat) |
| `⛔ BLOCKED #N — причина` | любой | блокировка, узел паркуется |
| `❓ QUESTION #N — кому: <роль>` | любой | вопрос, ответ — обычным комментарием |
| `♻️ RECLAIMED — клейм снят по таймауту` | координатор | перезахват зависшей задачи |
| `📌 DECISION — <суть>` | координатор/владелец | решение, обязательное к исполнению |

## Гарантии шины (проверены на прогонах)

1. **Скорость:** паркованный узел подхватывает задачу ≤120с после появления label; координатор отвечает на маркер ≤ одной минуты активной фазы. Ожидание — только блокирующим `wait-signal` (ETag-поллинг 60–120с, rate limit не расходуется).
2. **Свежесть:** перед КАЖДЫМ запуском ожидания — `git pull`; скрипты шины при ошибке (404/нет auth) падают ГРОМКО, не ждут молча; `wait-signal --version` печатает версию + SHA-256 (проверка клона машинна).
3. **READ ≠ CLAIM:** `👀 READ` — только подтверждение прочтения; захват задачи — `✋ CLAIM` (для роя) или label-переход. Полный канон словаря — KNOWLEDGE_BASE §5 комплекта воркфлоу.
3. **Атомарный claim:** взять задачу = снять `status:ready` + поставить `status:in-progress` одним действием; на issue ровно один `status:*`.
4. **Самовосстановление:** in-progress без движения дольше лимита размера (S=15м, M=60м) → пинг координатора → ещё один интервал → `♻️ RECLAIMED`, задача возвращается в ready. Смерть узла — штатное событие.
5. **Конфликты:** два узла увидели одну задачу — берёт тот, чей claim первый по времени; второй перечитывает issue и паркуется.
6. **Идемпотентность:** маркер никогда не публикуется дважды; перед действием узел перечитывает issue.
7. **Подпись узла:** все узлы могут работать под одним аккаунтом — личность живёт в подписи
   тела («— Роль · сессия/дата»). Комментарий/письмо без подписи не считается сообщением шины.
8. **Гигиена веток:** слитая ветка удаляется (после проверки merge-base); активные контуры
   и ветки на ревью не трогаются; неслитые замороженные — только по слову владельца.

## Интерактив для владельца

- Смотреть **борд** — там весь трафик в колонках; каждый маркер виден в issue.
- Вмешательство = один комментарий в issue (узлы на маркеры реагируют сами).
- Запуск новых узлов — единственное, что владелец делает руками (сессии поднимает только он), и один раз: парковочный промпт делает их автономными.

## Гигиена веток (обязанность координатора)

1. Ветка поставки удаляется сразу после слияния в main — проверка «целиком в main»
   (`merge-base --is-ancestor`) перед удалением обязательна.
2. Не удалять: активный контур исполнителя (платформа привязывает сессию к ветке),
   ветки на ревью, ветку тестового стенда.
3. Замороженные ветки с неслитыми коммитами не удаляются молча — только явным словом
   владельца (неслитая история — единственный носитель таких коммитов).
4. Агент работает от свежего origin/main (`fetch --prune` в начале сессии) — мёртвые
   ветки не должны попадаться на глаза и путать выбор базы.
