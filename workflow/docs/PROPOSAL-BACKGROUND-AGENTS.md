# ПРОПОЗИЦИЯ: Фоновые агенты непрерывной гигиены (background custodians)

> Черновик для обсуждения внешней коллегией. Автор: владелец + координатор, 11.11.2026.
> Статус: DRAFT — не утверждено. После обсуждения внешней коллегией — решение владельца (📌 DECISION).

## Проблема

Гигиена канона сегодня — событийная: аудит проводится, когда владелец его запускает
(аудит промптов 11.11, внешний аудит #69). Между аудитами дрейф накапливается
незамеченным. Прямое подтверждение — внешний аудит #69 (AUDIT-REPORT-69): 18 находок,
из которых минимум две — именно накопившийся дрейф живого состояния, который
непрерывный контур поймал бы за часы, а не за недели:

- **B-03** [`blocker`] — `project.json` хаба разошёлся со скриптами клейма и живыми метками репозитория;
- **H-06** [`high`] — серверный контур GitHub Actions не работает, карточки на живом борде дрейфуют от фактического состояния.

Аналог в индустрии: harness engineering OpenAI — «ручная пятничная чистка ИИ-мусора»
не прижилась; прижились фоновые агенты, открывающие точечные PR на рефакторинг.
Гигиена — не фаза, а процесс.

## Принцип

Фоновый агент — долгоживущий **read-only наблюдатель** с правом открывать
точечные issue / маркеры шины, но **без права мержа** и без права
трогать активные контуры исполнителей. Люди управляют — но не руками,
а через роли и границы.

## Роли (стартовый набор)

1. **`schema-sentinel`** — периодическая сверка: `project.json` ↔ живые метки GitHub ↔
   `schema/bus.json` ↔ скрипты клейма. Расхождение = маркер `👤 NEEDS-HUMAN` с диффом.
   Пилотное задание: находки B-03.
2. **`board-gardener`** — stale-патруль борда: in-progress без heartbeat → `📣 PING` →
   `♻️ RECLAIMED` по канону шины (гарантия 5); дрейф карточек от состояния веток
   (`board_link.py --audit-prs`, `--stale-report` уже есть — нужен живой цикл, а не ручной запуск).
   Пилотное задание: находка H-06.
3. **`doc-linter`** — машинная проверка актуальности документации: висячие ссылки,
   исполняемость примеров, соответствие регламентов `schema/bus.json`.
   (Сейчас это ловит только регрессионный тест при пуше, не живой репозиторий.)

## Границы (анти-мусор)

- Фоновый агент **не пишет код**: находка → issue/маркер шины; фикс — штатным циклом
  `ветка → PR → ревью не-автором`.
- Каждая роль — машинный гейт от ложных срабатываний: срабатывание только на
  машинно проверяемое расхождение (diff/label/ссылка), не «мне кажется».
- Серия ложных срабатываний = отзыв роли владельцем.
- Роли объявляются в оверлее проекта (`project.json`), ядро канона остаётся стерильным (ADR-0003).

## Форма решения

- Обсуждение внешней коллегией — комментарии в issue (адресно-нейтрально, распределение по аудиторам — за владельцем).
- Итог — либо закрытие как «не требуется», либо карточка реализации с ролями и гейтами.
