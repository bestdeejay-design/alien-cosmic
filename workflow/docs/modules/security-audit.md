## 1. Назначение

Модуль — прикладной комплект навыков и методической документации для проведения
аудита безопасности и пинтеста игровых и финтех-проектов силами ИИ-коллегии
(`auditor`/`researcher`/`reviewer`/`executor`). Ядро (`security-audit-core`) задаёт
обязательный порядок: scope и письменное разрешение → режим (Black/Grey/White Box)
→ проверки по чек-листам → отчёт. Граница ответственности: модуль даёт методику,
шаблоны и протокол работы агента; он не заменяет юридическую консультацию и не
проводит атаки вне согласованного scope.

## 2. Расположение

```text
skills/
├── security-audit-core/           # ядро: SKILL.md + support/ (методика, чек-листы, шаблоны, README)
├── security-audit-black-box/      # режимный навык: проверки снаружи, без доступов
├── security-audit-grey-box/       # режимный навык: часть доступов, стандартный продаваемый пакет
├── security-audit-white-box/      # режимный навык: полный доступ (код, схемы, конфиги)
├── security-audit-gaming/         # доменный навык: игровые проекты (экономика, аккаунты, платежи)
├── security-audit-fintech/        # доменный навык: финтех (деньги, регуляторные требования)
├── security-audit-reporting/      # навык сборки отчёта и исполнительской сводки
└── security-audit-core/support/   # методическая база: 00-…08-*.md, checklists/, templates/, README.md
docs/modules/security-audit.md     # этот паспорт
.claude/skills/security-audit-*/   # нативное зеркало CLI-клиента (раскатка install-skills)
.agents/skills/security-audit-*/   # нативное зеркало CLI-клиента (раскатка install-skills)
```

## 3. Публичный интерфейс

- `skills/security-audit-core/SKILL.md` — точка входа: обязательный порядок шагов,
  запреты и гейты качества; подключается всегда при любой проверке безопасности.
- Режимные навыки `security-audit-{black,grey,white}-box` — чек-листы проверок
  выбранного режима; подключаются поверх ядра.
- Доменные навыки `security-audit-gaming` / `security-audit-fintech` — доменные
  чек-листы; подключаются поверх режима.
- `security-audit-reporting` — сборка отчёта по шаблонам `support/templates/`.
- `support/` — методическая база: методология (`01-methodology.md`), процесс и RoE
  (`03-process-and-rules.md`), протокол ИИ-агента (`06-ai-agent-protocol.md`),
  чек-листы (`checklists/`), шаблоны документов (`templates/`), карта комплекта
  (`README.md`).

## 4. Зависимости

### Использует

| Модуль/компонент | Что именно | Зачем |
|---|---|---|
| Коллегия канона (`agents/`, `schema/bus.json`) | роли `auditor`/`researcher`/`reviewer`/`executor` | протокол работы агента опирается на роли и гейты коллегии |
| `scripts/install-skills` | раскатка в `.claude/` / `.agents/` | зеркало для нативных CLI-клиентов |

### Используется в

| Модуль/компонент | Что именно | Зачем |
|---|---|---|
| `skills/README.md` | каталог навыков | маршрут выдачи навыков координатором (см. #R2-05/доводку каталога — отдельная карточка) |
| `scripts/spawn-pack` | автоподбор навыков | комплект выдаётся исполнителям при задачах аудита |

## 5. Конфигурация

Собственной конфигурации модуль не имеет. Раскатка в зеркала выполняется
`python3 scripts/install-skills` (набор и цели — `project.json` канона). Секреты,
данные клиентов и параметры конкретных проектов в модуль не входят — только
методика и шаблоны.

## 6. Известные ограничения

- Комплект — методическая основа, не юридическая консультация; 152-ФЗ, PCI DSS и
  прочие регуляторные требования согласуются с юристом под конкретный проект.
- Генератор PDF-брифа (`scripts/build-partner-brief.py`) в каноне не заведён —
  техдолг #101 (R2-09); PDF собирается из Markdown по запросу.
- Санитизация пилотного материала (приватные литералы в `support/pilots/`) —
  отдельная карточка #102 (R2-02), в этот паспорт не входит.
- Ссылки из `SKILL.md` навыков на `support/` корректны в каноне, но обрываются в
  зеркалах после раскатки (R2-08 — отдельная карточка).
- Сверка зеркал в `tests/regression.py` пока сверяет только `SKILL.md` (R2-07 —
  отдельная карточка), дрейф `support/` она не ловит.
