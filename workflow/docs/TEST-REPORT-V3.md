# TEST-REPORT-V3 — сухой прогон цикла C вживую (issue #12, 03.11.2026)

> Исполнитель и ревьювер — реальные саб-агенты; координатор — основной агент.
> Требование issue #1: минимум 3 честные находки. Ниже — 5.

## Что прогонено
Полный цикл size:S-тира: labels + issue по шаблону → 👀 READ/✋ CLAIM → 🎯 CONCLUSION
(мини-аудит) → ✅ GATE OPEN координатора → ACTION (ветка work/12-mock-pilot, 1 коммит
4f7f33d) → 📬 DELIVERED (письмо 5 пунктов) → верификация поставки координатором
(merge-base, дифф, содержимое) → status:review → 🔎 VERDICT approve (ревьювер-саб,
5/5 пунктов чек-листа) → PR #13 → merge → 🏁 DONE → issue закрыт, ветка удалена.

## Находки
1. **Labels ядра не были созданы до пилота** — их заводил координатор по ходу.
   План внедрения шаг 1 предполагает прогон docs/create-labels.sh заранее; в живом
   проекте делать это до первой задачи, не во время.
2. **Борд Projects в пилоте не участвовал** — движение шло только по issue-меткам.
   Правило BOARD «сессия без карточки не существует» фактически не проверено:
   до продакшн-использования нужно настроить проект «Агенты — контроль» по
   PROJECTS-BLUEPRINT (включая запрет автоправила closed→Done).
3. **Канал external-узла (MAIL-файл) не тестировался** — исполнитель-саб имел прямой
   доступ к gh и отчитывался маркерами в issue. 📬 DELIVERED-ретрансляция координатором
   для узла без записи в issues осталась непроверенной — отдельный пилот.
4. **wait-signal-парковка не испытана** — сабы запускались адресно, ожидание гейта
   шло через координатора, а не поллинг. Проверить при первом живом рое.
5. **Задержка между GATE и фазой 2 требовала ручного пинка координатора** — саб
   завершился и ждал SendMessage; в живой сессии узел должен парковаться на
   wait-signal по issue (KB §5.2). Для сабов внутри одной сессии это норма,
   для независимых сессий — нет.

## Вердикт
Цикл C работоспособен вживую на size:S; словарь маркеров BUS↔KB подтверждён
практикой (post-фиксы PR #11). Блокеров не обнаружено. Комплект готов к утверждению
владельцем как канон; пункты находок 2–4 — в DEBT/план внедрения проекта-хоста.
