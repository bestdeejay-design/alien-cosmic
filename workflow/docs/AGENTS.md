# AGENTS — точка входа агента (вариант C)

> Статус: вариант C утверждён владельцем 03.11.2026 (см. `docs/README.md`).
> **Размещение:** шаблон хранится в `docs/`, в проекте точка входа размещается в корне.
> Если в проекте уже есть инструкции, не перезаписывай их: согласуй совмещение с
> координатором и сохрани действующие проектные правила (см. `docs/ADOPTION.md`).
> Читать: ≤ 5 минут. Детали — в регламентах.

## Кто ты здесь

Роли: владелец · координатор · исполнитель (роль из issue) · ревьювер · QA.
Твоя роль назначена label `agent:*` в твоём issue. **Нет назначенного issue — работы нет:**
спроси координатора, не ищи себе занятие. Внешний агент запускается только владельцем
по launch-пакету координатора.

## Холодный старт сессии (обязательно, по порядку)

1. Прочитать протокол (этот репозиторий) и статус `STATUS.md`.
2. Прочитать mailbox / статус-карточку проекта.
3. `git fetch --prune && git status -sb` — защита от протухшего локального git.
4. Нет назначенной задачи — работы нет: спросить координатора, не искать себе занятие.
5. Локальный git протух/откатился — сначала проверить и сохранить локальные
   изменения (commit/stash/копия), только потом восстановиться с origin;
   сохранение не гарантировано — эскалация координатору/владельцу (не молчаливая
   потеря), инцидент письмом координатору.

## Маршрут чтения (только это, в этом порядке)

1. Этот файл.
2. Регламент своей роли от корня репозитория: исполнитель — `docs/AGENT_RULES.md`,
   координатор — `docs/COORDINATOR_RULES.md`, шпаргалка — `docs/KNOWLEDGE_BASE.md`.
3. Своё issue целиком: бриф, критерии, размер, радиус, зависимости, ограничения.
4. Паспорт модуля и ADR, **указанные в issue**. Читать «весь репозиторий на всякий
   случай» вместо радиуса запрещено: радиус задал координатор, выход за него — question.

## Шесть абсолютных запретов

1. Не писать в главную ветку проекта — только ветка поставки. Ловит: координатор при слиянии.
2. **Внешний режим: поставка — пуш только своей ветки** после каждой задачи; главную ветку, чужие ветки и мержи не трогать никогда. Внутренний режим: мержить только точный коммит из approve ревьювера. Ловит: координатор сверкой письма и диапазона коммитов (AGENT_RULES §2).
3. Не начинать ACTION до гейта координатора (`phase:action`; для size:S — approve-комментарий). Ловит: ревьювер сверкой labels и комментариев.
4. Не трогать чужие зоны, замороженные зоны и файлы вне радиуса. Ловит: ревьювер по диффу и диапазону коммитов.
5. Не класть секреты в код, issues, PR, письма и launch-пакеты — никогда. Ловит: ревьювер; утечка = инцидент владельцу.
6. Не чинить найденный долг «заодно» и не поставлять без письма о поставке. Ловит: ревьювер; поставка без письма не существует.

## Сигналы между сессиями

Завершение, блокер, вопрос и ожидание человека оформляются маркер-комментарием
с фиксированной первой строкой (таблица — KNOWLEDGE_BASE §5): например,
`🏁 DONE #N — итог`, `⛔ BLOCKED #N — блокер: …`, второй строкой — подпись
роли/сессии. Владелец и агенты ждут эти сигналы скриптом `scripts/wait-signal`,
не держа сессию открытой. Задача из `status:ready` при рое берётся только захватом
(`✋ CLAIM`, KNOWLEDGE_BASE §5.1): выиграл захват — работаешь, проиграл — ждёшь.

## Если что-то непонятно или заблокировало

Создай issue по шаблону question (`.github/ISSUE_TEMPLATE/question.yml`), попроси
координатора перевести свой issue в `status:blocked`, фазу не меняй, жди ответа.
Полный цикл — AGENT_RULES §6.
Несогласие с решением — координатору комментарием, а не самодеятельностью в поставке.
