# Протокол работы ИИ-агента: как выполнять проверку тщательно и качественно

> **Обязательный файл для агента.** Без соблюдения этого протокола отчёт не принимается ревьюером.
> Агент работает внутри канона репозитория: роли `auditor`/`researcher`/`reviewer`/`executor`
> (`agents/` — описания ролей, `skills/` — навыки),
> доказательства по правилу достоверности (`PROTOCOL.md` §8).

## 1. Роли в проверке (коллегия)

| Роль канона | Роль в проверке | Выход |
|---|---|---|
| **auditor** (read-only) | Карта поверхности, инварианты, точки слома, threat model | `AUDIT_PACK`: цели, роли, потоки, что нельзя сломать |
| **researcher** (read-only) | Варианты проверки, приоритеты, сверка чек-листа с scope | `SPEC_PACK`: план проверок по режимам/домену |
| **reviewer** (не автор) | Предстартовый пинок (`REVIEWER_KICK`) + ревью находок и отчёта | `VERDICT` по находкам/отчёту, список «не проверено» |
| **executor** (свежий саб) | Исполнение проверок в scope, сбор доказательств | Находки по [templates/finding.md](templates/finding.md) + доказательства |

Правила коллегии: исполнитель не ревьюит сам себя; Волна 2 со сменой ролей для `size:M/L`
(файл `agents/collegium.md`). Для `size:S` — мини-аудит + независимый ревьювер.

## 2. Порядок работы агента (строго)

```text
1. Прочитай scope + RoE. Нет подписанного разрешения → СТОП, верни координатору.
2. Выбери режим (Black/Grey/White) и домен (игра/финтех) по [01-methodology.md](01-methodology.md).
   Зафиксируй в пакете. Смена режима — только изменением scope.
3. Подключи навыки: security-audit-core (всегда) + режим + домен + reporting.
   Пример: spawn-pack --skills security-audit-core,security-audit-grey-box,security-audit-fintech,security-audit-reporting
4. Построй AUDIT_PACK: карта целей, ролей, потоков денег/валюты, инварианты.
5. Построй SPEC_PACK: план проверок по чек-листу режима + домена, приоритеты по threat model.
6. Получи REVIEWER_KICK: ревьювер называет ловушки (что легко пропустить/нельзя трогать).
7. Исполняй проверки в scope и окне. Каждую находку — по finding-шаблону с доказательствами.
8. Не проверено — фиксируй отдельно с причиной (нет доступа, вне scope, стоп-условие).
9. Собери отчёт по [templates/final-report.md](templates/final-report.md). Без доказательств — не находка.
10. Независимое ревью отчёта. Исправь замечания. Только потом сдавай поставку письмом.
```

## 3. Запреты для агента (без исключений)

- Не атаковать вне scope, не трогать третьих лиц, не делать DoS/деградацию.
- Не удалять/портить данные, не эксфильтрировать сверх PoC, не использовать найденные секреты вне scope.
- Не выдумывать находки и не выдавать гипотезы за факты. Непроверенное — помечать как непроверенное.
- Не класть секреты/PII в отчёты, логи, коммиты, issues. Только маски/хеши.
- Не менять код клиента в проде (аудит read-only). Исправления — рекомендациями в отчёте.
- Не публиковать уязвимости до coordinated disclosure.
- Не подменять пинтест сканером: сканер — инструмент, а не методология.

## 4. Инструменты: что можно, что нельзя

| Инструмент | Роль | Правила |
|---|---|---|
| Сканеры (OWASP ZAP, Nuclei, Nmap и аналоги) | Recon и быстрый срез | Только в scope; результаты разбирать вручную, ложные срабатывания помечать |
| Прокси (Burp Suite и аналоги) | Ручные проверки API/веба | Тестовые аккаунты, staging; не атаковать прод без разрешения |
| SAST/зависимости (Semgrep, CodeQL, osv-scanner и аналоги) | White Box | Read-only доступ к коду; находки подтверждать PoC/контекстом |
| Скрипты агента | Повторяемость, сверки ledger/экономики | Версионируемые, с логами; без деструктивных действий |
| Эксплойты/обходы | Только PoC в scope | Минимально достаточные; без оружия массового поражения и без публикации |

Агент не должен запускать «авто-взлом» по всему интернету. Каждая цель — из scope.

## 5. Гейты качества (ревьюер проверяет)

- [ ] Scope и разрешение приложены, режим/домен зафиксированы.
- [ ] Чек-лист режима + домена пройден; «не проверено» перечислено с причинами.
- [ ] Каждая находка имеет шаги воспроизведения, фактический/ожидаемый результат, влияние, CVSS, рекомендацию.
- [ ] Нет находок без доказательств; нет секретов/PII открытым текстом.
- [ ] Отчёт содержит executive summary, методологию, ограничения, план исправлений, retest-план.
- [ ] Ревью проведено не автором; вердикт — по точному коммиту/версии отчёта.
- [ ] `python3 scripts/preflight` зелёный (для поставок в репозиторий).

## 6. Формат выхода агента

- **Пакет проверки:** режим, домен, scope-ссылка, карта поверхности, план, список «не проверено».
- **Находки:** по [templates/finding.md](templates/finding.md), каждая с ID и доказательствами.
- **Отчёт:** по [templates/final-report.md](templates/final-report.md) + executive summary.
- **План исправлений:** по [templates/remediation-plan.md](templates/remediation-plan.md).
- **Retest:** по [templates/retest-certificate.md](templates/retest-certificate.md).

## 7. Когда агент обязан остановиться и позвать человека

- Нужна эксплуатация за пределами PoC, деструктивный тест, social engineering, DDoS.
- Доступ к реальным деньгам/PII, продакшн-БД, секретам провайдеров.
- Юридические/регуляторные заключения, incident response, общение с регулятором.
- Любой стоп по [03-process-and-rules.md](03-process-and-rules.md) §3.

Остановка оформляется как `⛔ BLOCKED` / `👤 NEEDS-HUMAN` (формат шины задач, `BUS.md`),
а не молчаливым продолжением.
