# Аудит и пинтест игровых и финтех-проектов — комплект для ИИ-агента и для продажи услуги

> **Статус:** рабочий комплект v1 (2026-11-11). Для владельца, который пока слаб в терминологии:
> этот README — карта. Не нужно читать всё подряд. Иди по маршруту ниже.
>
> **Главное правило безопасности:** проверка проводится **только** на своих системах
> или по письменному разрешению владельца системы, в рамках согласованного scope.
> Без разрешения — это не пинтест, а правонарушение. См. [03-process-and-rules.md](03-process-and-rules.md).

## Что это такое простыми словами

Ты продаёшь не «взлом», а **проверку на прочность** с результатом, который клиент может
показать инвесторам, партнёрам, платёжным системам и своей команде:

1. **Находим** слабые места (уязвимости) — где можно украсть аккаунт, деньги, игровую
   валюту, данные игроков/клиентов, сломать экономику, обойти оплату.
2. **Доказываем** каждую находку воспроизводимым сценарием (PoC) — без выдумок.
3. **Оцениваем** риск: что будет, если этим воспользуются (деньги, репутация, закон).
4. **Даём план исправления** по приоритету и **перепроверяем** после исправлений (retest).

Клиент платит не за список страшилок, а за **отчёт + план + подтверждение исправления**.

## Система Black / Grey / White Box — коротко

| Режим | Что знает проверяющий до старта | Аналогия | Когда брать |
|---|---|---|---|
| **Black Box** (чёрный ящик) | Только публичное: сайт/приложение, URL, без кодов и схем | Злоумышленник снаружи | Первый внешний взгляд, релиз наружу, нет доступа к коду |
| **Grey Box** (серый ящик) | Часть: тестовые аккаунты, API-документация, архитектура, без полного кода | Злоумышленник с утечкой / инсайдер | Стандартный продаваемый пакет, есть staging и тестовые доступы |
| **White Box** (белый ящик) | Всё: исходный код, схемы БД, конфиги, логи, IaC | Аудитор внутри | Глубокий аудит перед инвестициями, после инцидента, финтех с деньгами |

Полное сравнение, что входит/не входит, ограничения и дерево выбора —
[01-methodology.md](01-methodology.md). Чек-листы по каждому режиму —
[checklists/black-box.md](checklists/black-box.md),
[checklists/grey-box.md](checklists/grey-box.md),
[checklists/white-box.md](checklists/white-box.md).

## Как идёт работа (жизненный цикл)

```text
1. Intake        → анкета клиента, что проверяем, зачем, сроки
2. Scoping       → scope: цели, режимы, что вне scope, стоп-условия, окно тестирования
3. Authorization → письменное разрешение + RoE + NDA (без этого — стоп)
4. Recon / Map   → карта поверхности: домены, API, роли, потоки денег/валюты
5. Testing       → проверки по чек-листу режима + домена, фиксация доказательств
6. Reporting     → отчёт: executive summary + технические находки + план исправлений
7. Remediation   → клиент исправляет (или ты консультируешь), приоритет по риску
8. Retest        → перепроверка исправлений, сертификат [templates/retest-certificate.md](templates/retest-certificate.md)
9. Handover      → передача материалов, рекомендации на будущее, подписка/повторный аудит
```

Детали, роли и гейты — [03-process-and-rules.md](03-process-and-rules.md) и [06-ai-agent-protocol.md](06-ai-agent-protocol.md).

## Что продаёшь (пакеты, кратко)

| Пакет | Режим | Для кого | Результат |
|---|---|---|---|
| **Express Black** | Black Box | Быстрый внешний взгляд перед релизом | Отчёт по внешней поверхности, топ рисков |
| **Standard Grey** | Grey Box | Основной продаваемый пакет для игр и финтеха | Полный отчёт + план + 1 retest |
| **Deep White** | White Box | Перед инвестициями, после инцидента, строгие партнёры | Глубокий аудит кода/архитектуры + отчёт + retest |
| **Retest** | Любой | После исправлений | Сертификат: исправлено / не исправлено / частично |
| **Подписка** | Grey/White | Компании с частыми релизами | Ежемесячный контур проверок + приоритетная поддержка |

Полное описание, что входит/не входит, сроки и модель цены — [08-service-packages.md](08-service-packages.md).

## Два домена — два разных набора рисков

- **Игровые проекты** ([04-gaming.md](04-gaming.md)): читы и обход античита, дюп валюты/предметов,
  подделка клиентского состояния, экономика и донат, RNG/лутбоксы, кража аккаунтов,
  DDoS и накрутка метрик. Деньги здесь — игровая валюта и донат.
- **Финтех и около финтех** ([05-fintech.md](05-fintech.md)): платежи и двойное списание,
  ledger/балансы, KYC/AML, API-ключи и секреты, PII и персональные данные, race conditions,
  идемпотентность вебхуков. Деньги здесь — настоящие, поэтому требования строже.

Один и тот же технический баг (например, IDOR) в игре может стоить «дюп предметов»,
а в финтехе — «кражу чужих средств». Поэтому доменный чек-лист обязателен.

## Качество: что значит «тщательно и качественно» для ИИ-агента

- Каждая находка — с **доказательством**: шаги воспроизведения, запрос/ответ, скриншот/логи,
  версия/коммит, дата. Нет доказательства — нет находки (см. [templates/finding.md](templates/finding.md)).
- **Независимое ревью**: находки проверяет не автор (коллегия канона, см. [06-ai-agent-protocol.md](06-ai-agent-protocol.md)).
- **Нет выдумок**: непроверенное помечается как «не проверено / требует ручной проверки»,
  а не выдаётся за факт. Правило достоверности (`PROTOCOL.md` §8) действует и здесь.
- **Безопасно**: без DoS, без удаления/порчи данных, без эксфильтрации сверх доказательства,
  без атак на третьих лиц. Стоп-условия — в [03-process-and-rules.md](03-process-and-rules.md).
- **Воспроизводимо**: другой проверяющий по отчёту может повторить сценарий.

## Дисклеймеры

- Комплект — **методическая основа**, а не юридическая консультация. Договор, NDA, обработка
  персональных данных и регуляторные требования (152-ФЗ, PCI DSS, требования платёжных систем,
  возрастные/игровые регуляторы) согласовывай с профильным юристом под конкретный проект.
- ИИ-агент **не заменяет** человека в вопросах эксплуатации, инцидентов и юридических решений.
  Атакующие действия вне scope, деструктивные тесты и работа с реальными персональными данными —
  только с участием человека и письменного разрешения.
- Результаты проверки действительны **на дату и версию** проверенного объекта. После изменений
  нужен retest или повторный аудит.
