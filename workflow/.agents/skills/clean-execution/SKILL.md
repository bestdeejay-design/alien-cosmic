# Навык: Чистая реализация в свежем контексте (`clean-execution`)

Используй этот навык при любом изменении кода, скриптов, конфигураций или документации.

## Чек-лист перед первой строкой кода

1. Проверь git-контур: `git fetch origin --prune && git status -sb`. Ты обязан быть на рабочей ветке (не `main`), отпочкованной от свежего `origin/main`.
2. Установи локальную защиту от прямого пуша в `main`: `python3 scripts/preflight --install-hooks`.
3. Перечитай `AUDIT_PACK`, `SPEC_PACK` и особенно **`REVIEWER_KICK`**: выпиши все названные ревьювером ловушки в свой план проверки, чтобы закрыть каждую тестом с первой попытки.

## Правила внесения изменений

- **Точный радиус:** меняй только файлы из разрешённого списка задачи. Понадобился файл снаружи — остановись и задай вопрос координатору, не расширяй дифф молча.
- **Предпочитай простоту и переиспользование:** используй существующие функции и схемы репозитория; не вводи одноразовых обёрток и не рефактори соседние строки.
- **Тесты без временных бомб:** никогда не зашивай текущую календарную дату в проверки окна времени — вычисляй относительно переданного `now` / фикстуры.
- **Не ослабляй существующие тесты:** если старый тест упал, проведи A/B-проверку на базовом коммите (`git stash` / `git worktree`) и чини причину, а не удаляй ассерт.

## Обязательная сдача (`Proof-of-Work`)

Перед коммитом и сдачей запусти:
```bash
python3 scripts/preflight
```
Включи полученную квитанцию `PREFLIGHT OK` (хеш, базу, число пройденных тестов) и честную карту тонких мест в отчёт коллегии и в письмо поставки.
