# Alien Cosmic — архитектура

Документ для развития проекта: как игра устроена сейчас и как она
проектируется к будущей сетевой игре.

## 1. Общая схема

```
attachInput (input.js)          — события → флаги/приказы через hooks
        │
        ▼
Game.tick (game.js)             — фиксированный шаг логики 30 Гц
  ├─ U.updateUnits              — приказы юнитов → движение (A*) → бой
  ├─ B.updateBuildings          — очереди, турели, гарнизоны, спавн
  ├─ U.updateProjectiles/Effects
  ├─ AIController.update        — экономика и волны ИИ
  ├─ Fog.recompute (каждые 3 тика)
  └─ checkEnd                   — победа/поражение
        │
        ▼
Game.render(alpha)              — интерполяция между тиками, Canvas 2D
```

- **Логика и рендер разделены.** `tick()` не зависит от кадровой частоты;
  рендер интерполирует позиции (`prevX/prevY → x/y`) по остатку аккумулятора.
- **Единый контракт сущности**: `kind: 'unit' | 'building' | 'mineral'`,
  `side: 'player' | 'enemy'`, x/y в пикселях мира, hp, cfg.
- **Весь баланс — в `config.js`**: юниты, здания, улучшения, биомы, профиль
  ИИ. Балансировка не трогает код.

## 2. Приказы — это данные

Любое действие игрока/ИИ сводится к объекту-приказу в `unit.order`:

| kind | поля | поведение |
|---|---|---|
| `idle` | — | автопоиск цели (бойцы) / раненых (медики) |
| `move` | x, y | путь A* → стоп по прибытии |
| `attackMove` | x, y, target | идти к точке, вступать в бой по дороге |
| `attack` | target, auto | преследовать и стрелять; `auto` — с «поводком» |
| `gather` | target, phase | кристалл → майнинг → сдача → повтор |
| `build` | target, resume | стройка; `resume` — кристалл для авто-возврата |
| `repair` | target, resume | ремонт; после — авто-возврат к добыче |
| `garrison` | target | зайти в бункер |

Это ключ к сетевой игре: **команда сети = та же структура приказа**.
Реплей/сетевой ввод = список `(тик, приказ, цель)`.

## 3. Авто-режимы (Ф1) — где живут

- `units.js`: `orderAttackMove`, `updateAttackMove` (сканирование через
  `acquireTarget`, сброс маршрута при смене цели), `busyDefence` (огонь на
  задаче + лечение медиком на марше), `resumeGather` + `currentCrystal`
  (авто-возврат), `nearestCrystal` (анти-толпа: штраф `TILE*2.2` за
  закреплённого рабочего).
- `buildings.js`: `findSpawnSpot` (периметр здания, тайл свободен и
  `≥ 24px` до живого юнита), `trySpawnTrained` (юнит ждёт выхода, если
  периметр заперт — не появляется в корпусе), rally-на-кристалл.
- `input.js`: режим `attackMoveMode` (клавиша A → crosshair → ЛКМ),
  `doubleSelect` (двойной клик — все такие же на экране).
- `game.js`: хук `issueAttackMove` (формационные офсеты `formationOffsets`).

## 4. Что уже «сетевой-готово»

1. **Фиксированный шаг логики** (30 Гц, аккумулятор, потолок кадра) —
   база детерминизма и лаг-компенсации.
2. **Приказы-команды** (см. §2) — ввод можно логировать и пересылать.
3. **Чистое состояние партии** — объект `st` без ссылок на DOM (кроме
   `st.game`-ручки на сервисы звука/UI, которые в симуляцию не входят).
4. **A* без таймеров реального времени** — путь зависит только от карты.
5. **Камера/ввод — вне логики** — сетевой клиент просто шлёт приказы.

## 5. Что потребуется для сети (Ф7)

По порядку внедрения:

1. **Сеяный RNG.** Заменить `Math.random()` в логике (`busyDefence`-эффекты,
   разбросы, ИИ) на `st.rng = mulberry32(seed)` — визуальный шум оставить
   на `Math.random`. Проверка детерминизма: два прогона с одинаковым
   списком команд дают идентичные `st` (хэш позиций/HP на тике N).
2. **Командный журнал.** Все приказы проходят через одну точку
   (`issueRMB`, `issueAttackMove`, `tryPlace`, `train`, `startResearch`,
   ИИ-приказы) → обернуть в `submitCommand(tick, cmd)`. Реплей =
   `seed + журнал`.
3. **Сервер-авторитет.** Node + WebSocket: рассылает команды, тикает
   симуляцию (модули уже изоморфны — логика не трогает DOM),
   клиенты рендерят с интерполяцией. Либо WebRTC P2P с хост-арбитром.
4. **Синхронизация ввода.** «Lockstep на задержке»: команда игрока
   применяется на тике `текущий + K`; при потере пакета — пересинхронизация
   снапшотом (сериализация `st`).
5. **Соревновательный слой**: рейтинги (Elo/Glicko) по режимам, сезонные
   таблицы, редактор карт (формат генератора уже параметрический —
   `{seed, biome, lakes, rocks, rich, base}`).

## 6. Проверки

- `scripts/check.mjs` — статический валидатор: синтаксис каждого модуля,
  существование относительных импортов и именованных экспортов,
  ссылки `index.html`, отсутствие внешних запросов.
- Ручной smoke: кампания → миссия 1 → добыча → казарма → очередь 3 юнитов
  (спавн в цепочку) → стройка турели → A+ЛКМ в атаку → двойной клик.
- Перед каждым push: `node scripts/check.mjs` из корня репозитория.

## 7. Соглашения

- Чистый JS, ES-модули, относительные импорты `./js/...` (GitHub Pages).
- Комментарии объясняют «почему», а не «что»; каждый багфикс несёт историю.
- Баланс — только через `config.js`; магические числа в логике запрещены.
- Названия по фракциям — через `fname(cfg, faction)` / `fdesc(...)`.
